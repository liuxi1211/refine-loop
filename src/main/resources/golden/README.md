# 黄金样本目录约定（`golden/{unit_id}/`）

> 用途：interpret 单元的输出质量回归基线。prompt / 模型 / Schema 变更后回放比对，
> 判定标准与执行方式见《核心能力体系设计详案》5.8（漂移 1 档以内占比 ≥80% 通过；
> 漂移 ≥2 档、出现事实表外指标、标签越界，任一即判回归失败）。

## 目录结构

```
golden/{unit_id}/
├── {sample_id}.input.json      输入快照：buildFactsPayload 的产物（facts_json）
├── {sample_id}.expected.json   人工确认过的判断块（判断块部分，不含报告正文）
└── {sample_id}.report.md       人工确认过的报告正文（可选，用于正文数字纪律回归）
```

`sample_id` 用 `{ts_code}-{trade_date}`，例如 `000001.SZ-20261126`。

## 录制纪律

1. **人工确认后才入库**：样本的 `expected.json` 必须是人看过并认可的输出，不能直接拿模型输出当基线；
2. **样本量 10~15 个**：覆盖不同结论档位（明显偏低/偏低/合理/偏高/明显偏高）与不同数据状态（正常/降级）；
3. **一次录制对应一个单元版本**：单元升版后旧样本保留（用于跨版本比对），但回归判定只对当前版本生效；
4. **输入快照必须是当初真实喂给模型的那份**：否则漂移无法归因到 prompt 还是数据。

## 与校验链的关系

黄金样本回放不走 LLM 重试，只对 `expected.json` 跑一次 L3 五重校验——样本自身必须能通过校验链，
否则说明样本或规则集写错了（这也是一条自检：样本即测试夹具）。
