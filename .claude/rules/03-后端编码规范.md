# 03 后端编码规范（类与方法设计）

> 语言：Java 21。风格基线：4 空格缩进、UTF-8、LF、单行 ≤ 120 字符、无通配 import。
> 强制等级：可机械判定的为 `[L2]`（`ArchitectureRulesTest` + 编译）；语义类为 `[L3]`。

## 1. 命名总表（后缀即契约）

新增类**必须先在后缀表里找到位置**；找不到说明它在承担两种职责，应该拆。

| 后缀 | 位置 | 职责 | 允许依赖 | 示例 |
|---|---|---|---|---|
| `*Controller` | `web/**` | HTTP 适配：解析、校验、调服务、包 `Result` | 领域服务、web DTO | `TablesController` |
| `*Service` | 领域包 | 用例编排、事务边界 | `data`、`common`、同域模型 | `IngestJobService` |
| `*Facade` | 领域包 | 跨多个 service 的粗粒度入口（对外稳定） | 同域 service | `IngestFacade` |
| `*Mapper` | `data/mapper` | 表访问 / 固定查询 | MyBatis | `IngestLogMapper` |
| `*Provider` | `data/provider` | 动态 SQL 生成 | 注册表 | `TushareSqlProvider` |
| `*Entity` | `data/entity` | 表结构映射（可变 POJO） | MyBatis-Plus 注解 | `IngestLogEntity` |
| `*View` | 领域 `dto` | API 响应视图（不可变 record） | 无 | `IngestJobView` |
| `*Request` | `web/**` | API 请求体（record + 校验注解） | jakarta validation | `DailyToggleRequest` |
| `*Params` | 领域包 | 参数对象（替代 >4 参方法） | 无 | `OpsParams` |
| `*Props`/`*Properties` | `config` | 配置绑定 | Spring Boot | `IngestProperties` |
| `*Config` | `config` | Spring 装配 | 任何（装配根） | `MyBatisPlusConfig` |
| `*Registry` | 领域包 | 元数据/实例注册表（只读） | 无 | `TushareTableRegistry` |
| `*Writer` | 领域包 | 唯一落库出入口 | `data` | `IngestTableWriter` |
| `*Store` | 领域包 | 轻量持久化封装（日志/快照） | `data` | `QualityCheckLogStore` |
| `*Gate` | 领域包 | 校验/门禁（返回报告而非抛异常） | 同域 | `DataQualityGate` |
| `*Exception` | 领域包 | 领域异常（`RuntimeException` 子类） | 无 | `TushareApiException` |
| `*ErrorCode` | 领域包 | 错误码枚举（实现 `ErrorCode`） | 无 | `CommonErrorCode` |
| `*Enum` | `common/enums` 或领域 | 字典枚举（实现 `DictEnum`） | 无 | `EnableStatusEnum` |
| `*Aspect` / `*Filter` / `*Interceptor` | `common`/`config` | 横切 | 视场景 | `LocalCacheAspect` |
| `*Handler` | 框架钩子 | 字段填充 / 类型处理 / 异常出口 | 框架 | `AuditMetaObjectHandler` |
| `*Utils` / `*s` | `common/util` | 无状态工具（`final` + 私有构造） | JDK | `DateTimes`、`Asserts` |

**命名禁令**

- 禁止 `*Impl` 作为**唯一**实现的后缀（接口只有一个实现时，接口本身往往多余）。存量 `IngestFacadeImpl` 保留，新代码优先「类即实现」。
- 禁止 `*Helper`、`*Util2`、`*Manager`、`*Processor`、`*Handler2` 这类无信息后缀。
- 禁止 `*DTO` / `*VO` / `*BO` / `*PO` 混用：本项目统一 `*View`（出参）、`*Request`（入参）、`*Entity`（表映射）。
- 禁止 `*Dtos` 容器同时装请求体和响应体（请求体归 `web`，响应体归领域 `dto`）。
- 品牌拼写统一 `MyBatis`（类名中也写 `MyBatis…`，不用 `Mybatis…`）。

## 2. 类设计

### 2.1 谁拥有什么

| 规则 | 说明 |
|---|---|
| 单一职责 | 一个类只有一个"变化原因"；`IngestJobService` 同时管 5 种策略 + 页循环 + 落库，是反例（已登记拆分） |
| 构造器注入 | 100% 构造器注入（现有代码已做到）；禁止 `@Autowired` 字段注入 |
| 依赖数 ≤ 7 | 超过说明它在编排太多东西，拆 Facade 或用参数对象 |
| 类行数 ≤ 400 | 超阈值先看是否混了"查询 + 写入 + 格式化"三种职责 |
| 优先不可变 | 值对象/DTO 一律 `record`；需要可变才用类（MyBatis 实体） |
| 禁止继承业务类 | 继承只允许 `BaseEntity`（实体基类）与框架基类；组合优先 |
| 工具类 | `public final class` + 私有构造；方法全 `static`；无状态 |
| 禁止静态可变状态 | `static` 字段只能是 `final` 常量或不可变集合（`List.copyOf`）；进程级锁要注释说明为什么不能用实例锁 |
| 枚举承载语义 | 状态/类型/模式用枚举，不用 `String` 常量 + `switch` 散落（现状：`"SUCCESS"` 字面量散布 20+ 处，属整改项） |
| 常量归位 | 通用 → `common/constant`；领域 → 领域枚举/注册表；**不要**在 service 里 `private static final String` 堆业务字面量 |

### 2.2 实体、值对象、视图的边界

```
HTTP JSON  ←→  *Request / *View（record，无框架注解，字段名即契约）
                ↕ 显式转换（在 service 或专用 mapper 方法里）
            *Entity（可变 POJO，@TableName，字段与列一一对应）
                ↕ MyBatis
            SQLite 表
```

- **Entity 不出 `data` 层**：不允许作为 Controller 返回值、不允许出现在 `web` 包的任何签名里（红线 4）。
- **View 不做业务判断**：只承载数据；需要派生值（如 `health`）由 service 计算。
- **转换写在哪**：单表 CRUD 在 service 内私有方法；复杂装配在 `<域>Assembler`（可选）。
- Entity 字段：`id` + 与列同名的驼峰字段；**不要**加 `@TableField(exist=false)` 的"顺便字段"。

### 2.3 新实体用 Lombok 吗

- 现状 5 个实体是手写访问器（无 Lombok 使用）。
- **新实体统一用 `@Getter @Setter`**（减少 100+ 行样板），禁止 `@Data`（会生成 `equals/hashCode` 与可变字段冲突）、禁止 `@Builder` 用在实体上（MyBatis 需要无参构造）。
- 存量手写实体**不要求**改写（无行为收益），但一旦改动其字段，顺手换成 `@Getter @Setter`。
- `record` 不叠加 Lombok 注解。

### 2.4 配置类

- 配置绑定一律 `@ConfigurationProperties(prefix=...)` + `@ConfigurationPropertiesScan`；`@Value` 只允许出现在"探测型/一次性"场景（当前仅 1 处）。
- 每个 Properties 类必须加 `@Validated` + 约束（`@Min`/`@NotBlank`），让配置写错在启动期暴露，而不是运行期静默降级。
- 配置前缀：本项目统一 `refine-loop.*`；已有 `tushare.*`（历史）保留，新增用 `refine-loop.<域>.*`。
- `@Configuration` 只做装配，不写业务逻辑；不注入 `*Mapper` 到业务 service 以外的地方。

## 3. 方法设计

### 3.1 方法做一件事，名字说清做什么

| 语义 | 允许的动词 | 返回 | 禁止 |
|---|---|---|---|
| 按主键/唯一键取**必然存在**的 | `get` | 值（不存在抛 `ApiException.notFound`） | 返回 `null` 而不说明 |
| 按条件查**可能不存在**的 | `find` | `Optional<T>` | `get` + `null` |
| 取集合 | `list` | `List<T>`（空集合，非 `null`） | 返回 `null` |
| 分页 | `page` | `PageResult<T>` | 自己拼 limit/offset |
| 计数/存在性 | `count` / `exists` | `long` / `boolean` | `getCount` |
| 创建 | `create` | 新对象/ID | `insert` |
| 更新 | `update` / `markXxx`（状态迁移） | `void` / 影响行数 | `save`（语义模糊） |
| 删除 | `delete` / `remove`（业务删除） | `void` / 影响行数 | `del` |
| 动作 | `trigger` / `run` / `retry` / `toggle` / `refresh` / `evict` | 结果对象 | `doXxx` |
| 前置条件 | `require`（不满足抛 400/404） | 校验后的值 | `check`（返回 boolean 易被忽略） |
| 归一化 | `normalize` | 规范值 | — |
| 解析外部数据 | `parse` / `resolve` | 领域对象 | — |
| 布尔判断 | `isXxx` / `hasXxx` / `canXxx` | `boolean` | `checkXxx` |

**同一个语义只允许一个动词**。禁止出现 `find`/`get`/`query` 三种写法查同一个东西（现状：三种都有，属整改项）。`query` 仅用于「查询对象/查询条件」的名词（`PageQuery`）。

### 3.2 参数与返回

| 规则 | 说明 |
|---|---|
| 参数 ≤ 4 | 超过用参数 record（`IngestJobRequest`、`PreviewSpec`），不要用 `Map<String,Object>` 传参 |
| Controller 的 HTTP 绑定方法例外 | `@GetMapping` 方法的 `@RequestParam`/`@PathVariable` 个数不受 ≤4 限制（那是绑定声明，不是业务参数）；业务参数一多就收进 `*Request`/`*Spec` |
| 禁止无名字面量参数 | `trigger(table, "INCR", null, null)` → 用 `WriteMode.INCR` + 参数对象 |
| 禁止 `boolean` 位置参数 | `snapshot(true)` 不可读；用枚举 `SnapshotMode.LIVE` 或拆两个方法 |
| 禁止 `Optional` 作参数 | `Optional` 只用于**返回值**；入参用可空引用 + `@Nullable` 语义注释 |
| 禁止返回 `Map<String,Object>` 作为业务结果 | 字段名无编译期保护；用 record（`PreviewResult` 的 `rows` 是动态列，属合理例外） |
| 空集合优于 `null` | 统一 `List.of()` / `Optional.empty()` |
| 可变集合不直接返回 | 返回 `List.copyOf(...)` 或不可变视图 |

### 3.3 方法长度与嵌套

- ≤ 50 行；嵌套 ≤ 3 层（`if/for/try` 之和）；
- 提前返回（guard clause）代替深层 `if/else`；
- `switch` 必须穷尽（用 `switch` 表达式 + 枚举，不要 `default` 兜底业务分支）；
- 一个方法里不混合"查库 + 计算 + 格式化 + 写日志"。

### 3.4 参数对象示例

```java
/** 一次接入作业的入参（替代 6 个位置参数）。 */
public record IngestJobRequest(
        TableDef table,
        WriteMode mode,
        String startDate,   // 可空，yyyyMMdd
        String endDate,     // 可空
        AtomicLong fetched,
        AtomicLong written) {

    public static IngestJobRequest of(TableDef table, WriteMode mode) {
        return new IngestJobRequest(table, mode, null, null, new AtomicLong(), new AtomicLong());
    }
}
```

## 4. 校验与契约

| 场景 | 做法 |
|---|---|
| HTTP 入参 | `@Valid` + jakarta 约束（`@NotBlank`/`@Min`）+ 自定义 `@EnumCode(枚举)`；错误统一走 `GlobalExceptionHandler` → 400 |
| 服务层前置条件 | `Asserts.notNull(...)` / `Asserts.isTrue(...)`（抛 `ApiException.badRequest`）；**不要用 `Objects.requireNonNull`**（会变成 500 且文案是英文堆栈） |
| 领域不变量 | 构造器/工厂里校验，抛领域异常 |
| 外部数据 | 解析后校验必填列与值域，不合法 → 记录 `DataQuality`/跳过，不要静默写入脏数据 |
| 表名/列名等标识符 | 必须白名单（`TushareTableRegistry` / `OpsParams.requireTable`），禁止直接拼进 SQL |

校验**位置**：边界（Controller）做格式/范围；服务做业务规则；数据库做唯一性/非空（最后一道）。三层都要有，不许"以为上层校验过了"。

## 5. 异常与错误码

```
用户/调用方错误 → ApiException + ErrorCode（400/404/409）
依赖不可用     → 领域异常包装 → 503（DataAccessException 已统一处理）
程序缺陷       → 不捕获，交给 GlobalExceptionHandler → 500 + error 日志 + traceId
```

| 规则 | 说明 |
|---|---|
| 只抛 `ApiException`（可预期）或让异常上抛（不可预期） | 不要自定义 `RuntimeException` 让全局兜底成 500 |
| 错误码集中登记 | `common/error/CommonErrorCode`（通用）+ 各域 `*ErrorCode`（业务码段见 04 §3.3） |
| 异常消息面向用户 | 中文、可操作、不含堆栈/SQL/类名 |
| 禁止吞异常 | `catch` 必须：记日志（含 traceId）→ 转换 → 或明确降级并注释原因；**空 catch 一律驳回** |
| 禁止 `catch (Throwable)` | 会吃掉 OOM/中断信号 |
| 禁止 `printStackTrace()` / `System.out` | 用 `log.error("...", e)` |
| 外部调用异常要分型 | 网络/限流/参数/业务四类分开，决定是否重试（`Tushare*Exception` 是范例） |

**降级策略**：外部依赖失败时，能降级则降级**且必须留痕**（日志 warn + 返回值标注 stale），不能"静默返回默认值"（现状 `SysConfigService` 两处静默 `catch` 是反例，整改中）。

## 6. 日志

| 级别 | 何时 |
|---|---|
| `error` | 只有"明确异常"：程序缺陷、数据损坏、依赖不可恢复；必须带异常对象 |
| `warn` | 可预期失败：业务拒绝、外部限流/重试、降级发生 |
| `info` | 里程碑：作业开始/结束、状态迁移、启动完成（生产保留） |
| `debug` | 排查细节：SQL、每标的进度、参数快照（生产关闭） |

- 日志必须带 traceId（`TraceContext` 自动注入 MDC），禁止手动拼；
- **禁止打印大对象**：行情列表/LLM 响应只打长度与摘要（`rows=1500`）；
- 禁止把 token/key/密码/完整 payload 打进日志（`MaskUtils` 脱敏）；
- 日志文案统一中文，格式 `动作 + 关键标识`：`接入作业成功 table=daily jobType=INCR fetched=…`；
- 循环内日志必须 `debug` 或聚合后打一条 info。

## 7. 时间、ID、随机

| 项 | 规则 |
|---|---|
| 当前时间 | 注入 `java.time.Clock`（已有 `Clock` Bean），禁止 `LocalDateTime.now()`/`new Date()` |
| 时区 | 固定 `Asia/Shanghai`，统一常量（禁止各 service 自己 `ZoneId.of("Asia/Shanghai")`，现存 3 处整改） |
| 日期格式 | 只用 `common.constant.DatePatterns` 常量 + `common.util.DateTimes` 格式化器；禁止内联 `"yyyyMMdd"`（现存 5 处整改） |
| 业务日期 | `String`（`yyyyMMdd`）贯穿：DB `CHAR(8)`、API、日志一致 |
| 时间戳落库 | `LocalDateTime` + `SqliteLocalDateTimeTypeHandler`；截断到秒 |
| ID | `common.util.Ids`（`J-…`/`BF-…`/`run_id`），禁止 `UUID.randomUUID()` 散落（需要时集中到 `Ids`） |
| 随机 | 测试可用 `MutableClock`；生产禁止无种子的 `Math.random()` 影响业务 |

## 8. 事务与并发

| 规则 | 说明 |
|---|---|
| `@Transactional` 只在 service 写方法 | 不放在 Controller（红线）、不放在 Mapper |
| 只读查询不加事务 | 或 `readOnly = true` |
| 事务内禁止 HTTP/LLM/文件 IO | 会把事务拖成秒级，SQLite 写锁全表阻塞 |
| 批量写 | `MyBatisBatchExecutor`：500 行/批 + 每批短事务；同一事务内不混用 `ExecutorType` |
| 自调用失效 | `this.method()` 不经过代理，`@Transactional` 无效；需要时拆到另一个 Bean |
| 并发 | 用虚拟线程（已开）+ `ThreadPools`；共享可变状态只在单例内部且加锁并注释；跨进程互斥用 DB（`sys_config` 标记） |
| 幂等 | 外部可重试的动作必须有幂等键（run_id / 唯一索引），重复执行不产生脏数据 |

## 9. 注释与文档

1. **每个 public 类型必须有类级 Javadoc**，且写三件事：**职责 / 依赖方向 / 不变量或约束**。现有 126/126 已覆盖，保持。
2. **public 方法 Javadoc 的必写场景**：有副作用、有前置条件、可能抛异常、返回值语义不直观、被跨包调用。
3. 不写"废话注释"（`/** 获取名字 */ getName`）；注释解释 **为什么**，不是 **是什么**。
4. 禁止在 Javadoc 里写易失的排期/任务号（"T17 接告警"、"Step6 契约 §9.2"）作为唯一说明——要写清行为，任务号放提交信息。
5. 复杂 SQL / 正则 / 位运算必须有一行注释说明意图。
6. `// ==== 分节 ====` 用于 >200 行类的逻辑分区（现有风格，保留）。
7. 修改代码时同步修正过时注释（注释与代码不一致视为缺陷）。

## 10. 格式与风格（`.editorconfig` 已固化）

| 项 | 值 |

## 12. 自查清单

- [ ] 方法名用 §3.1 的动词，参数 ≤4，无 `boolean` 位置参数；
- [ ] 异常不吞、日志级别正确、不打印大对象；
- [ ] 时间/ID/日期格式走统一工具；
