# 04 接口契约规范

> 面向：后端 `web` 层 + 前端 `api` 层。契约的唯一目的：**两边永远对得上，且对不上时立刻发现**。
> 强制等级：`Result` 包装/HTTP 语义/分页形态为 `[L2]`（ArchUnit + 控制器单测）；路径与命名规范为 `[L3]`。

---

## 1. URL 规范

**前缀到底解决什么问题**：让反向代理在响应体产生**之前**就能判定「这个请求由谁处理」。
前端是 SPA——页面不是磁盘文件（只有一个 `index.html`，`/users` 这类路径由 JS 渲染），
而后端与静态资源同源部署在 Nginx 后面，代理必须按 URL 决定「找文件还是转 8080」。
**文件扩展名描述响应体形态，路径前缀描述处理器身份**：在 MPA 里两者恰好重合，在 SPA 里必须把后者显式写回 URL。

收益是**代理配置不随业务域数量增长**：当前 5 个首段，规划中还有 `runs`/`candidates`/`stocks`/`judgments`/`reports` 等十几个；
枚举式配置每加一个域要同步改 Nginx 与 dev 代理两处，漏一处就是「生产 404、本地正常」。

**前提（很重要）**：前端与 API **同源部署**（Nginx 托管静态 + 反代 `/api`）。
若改成跨源部署——浏览器直连后端端口，或独立 `api.` 子域——这条约束自动失效，届时应当去掉前缀：
跨源时 URL 本身已带处理器身份，CORS 的复杂度也已经支付了那份成本。
换句话说，`/api` 不是「规范要求」，而是「同源 + SPA」这个前提下的结论。

**前缀只在一个地方挂载**：`config.WebMvcConfig#configurePathMatch` 的 `addPathPrefix`，作用于 `web` 包。
Controller 内**禁止手写** `/api`（由 `ApiPathPrefixTest` 拦截），只写自己的资源路径，
例如 `@RequestMapping("/users")` 对外就是 `/api/users`。

```
/api/health                     探活（无需鉴权）
/api/common/{dicts,cache}       公共基础设施
/api/ops/{tables,ingest,quality,stats}   运维读模型（数据中心运维台）
/api/{域}/{资源}                 业务域（M1 起：/api/analyses、/api/judgments …）
```

| 规则 | 说明 |
|---|---|
| **所有接口必须在 `/api` 下** | 前提：同源部署（见上）。前缀由 `WebMvcConfig` 统一挂载，Controller 不手写；裸前缀（`/tables`）已废弃 |
| 运维接口统一挂 `/api/ops` | 与业务域隔离，便于整段加鉴权/限流 |
| 路径全小写，多词用 `-` | `/daily-toggle`、`/backfill-plan`；禁止 `/dailyToggle`、`/daily_toggle` |
| 资源用**复数名词** | `/tables`、`/jobs`、`/judgments`；单资源用 `/{id}` |
| 子资源用路径嵌套 | `/tables/{table}/jobs`、`/jobs/{id}/retry` |
| 非 CRUD 动作用**动词末段** | `/run`、`/retry`、`/backfill`、`/daily-toggle`、`/refresh`、`/evict`；动词只允许下表 |
| 路径变量不带类型后缀 | `{table}` 而非 `{tableName}`；`{id}` 用业务编号时命名为 `{judgmentId}` |
| 查询参数 camelCase | `?start=20260101&size=20`；多词 `?tradeDate=` 而不是 `?trade_date=` |
| 不在 URL 里传 token | 鉴权走 `Authorization` Header（见 §8） |

**动词白名单**：`run` `retry` `backfill` `toggle` `refresh` `evict` `verify` `replay` `cancel`。新增动词需评审。

### 1.1 HTTP 方法

| 方法 | 语义 | 幂等 |
|---|---|---|
| `GET` | 查询，无副作用 | ✓ |
| `POST` | 创建 / 触发动作 | ✗（触发动作必须自带幂等键或互斥保护） |
| `PUT` | 全量替换（慎用） | ✓ |
| `PATCH` | 局部更新（本项目优先用明确的动作端点替代） | ✗ |
| `DELETE` | 删除/清空 | ✓ |

禁止用 `GET` 触发写操作（爬虫/预取会误触发）。

### 1.2 HTTP 状态码

- **业务接口 HTTP 恒 200**：语义由 `Result.code` 表达。前端 `http.ts` 只认 `code`，非 200 一律按"网络/网关错误"处理。
- 例外：静态资源、`/swagger-ui`、容器级错误（404 路径不存在由 `NoResourceFoundException` 转成业务 404 码，仍返回 200）。
- 理由：单前端 + 单后端，一套语义即可；避免"HTTP 400 + body 里又是 code"的双重真相。

## 2. Controller 契约（红线）

```java
@RestController
@RequestMapping("/ops/tables")          // 对外是 /api/ops/tables：/api 由 WebMvcConfig 统一挂载
public class TablesController {

    private final TableOpsService tableOpsService;   // 只依赖领域服务

    @GetMapping("/{table}")
    public Result<OpsViews.TableDetail> detail(@PathVariable String table) {
        return Result.ok(tableOpsService.detail(table));   // 校验在服务/参数层
    }
}
```

| 必须 | 禁止 |
|---|---|
| 返回 `Result<T>`（含 `Result<Void>`） | 返回裸对象 / `Map` / `ResponseEntity<业务对象>` |
| 只解析参数 + 调服务 + 包装 | 写库、拼业务文案、算业务状态、睡眠/重试 |
| 入参用 `*Request` record（`@Valid`） | 用 `Map<String,Object>` 接请求体 |
| 路径/参数校验用 `@EnumCode`、`Asserts`、`OpsParams` | 手写 `if` 拼中文错误串（重复且易漏） |
| `@Transactional` 不出现 | 在 Controller 开事务 |
| 每个端点一行 Javadoc：`GET /xxx：做什么（失败语义）` | 无注释的多端点控制器 |

`web` 不得 import `..data.mapper..` / `..data.entity..`（`ArchitectureRulesTest` 拦截）。

## 3. 统一响应与错误码

### 3.1 响应信封 `[L1]`

```json
{ "code": 0, "msg": "ok", "data": { } }
```

| 字段 | 规则 |
|---|---|
| `code` | `0` 成功；其余见 §3.3；**前端只以 `code === 0` 判定成功** |
| `msg` | 面向用户的中文；失败时说明**怎么改**；不得含堆栈/SQL/类名；500 时附 `traceId=…` |
| `data` | 成功时的业务体；失败时为 `null`；列表类成功返回空数组而不是 `null` |

### 3.2 分页 `[L1]`

统一 `PageResult<T>`：`{ items: T[], total: number, page: number, size: number }`

- `page` 从 1 开始；`size` 1~100（`PageQuery.MAX_SIZE`）；
- 非法值**直接 400**，不做静默截断（列表接口不能"越界却返回第 1 页"）；
- 后端唯一实现：`PageQuery.of(page,size)` + `PageResults.of(...)`；禁止各服务手搓 `LIMIT/OFFSET`；
- 排序：固定排序或白名单字段（防注入）；分页必须带唯一列兜底，保证翻页稳定。

### 3.3 错误码分段（新增码必须登记）

| 段 | 用途 | 归属 |
|---|---|---|
| `0` | 成功 | `CommonErrorCode.OK` |
| `400`–`504` | 沟通层（与 HTTP 语义对齐） | `CommonErrorCode`，**不新增** |
| `1001`–`1099` | 通用业务（校验失败/重复/未就绪/状态拒绝/不支持） | `CommonErrorCode` |
| `2001`–`2999` | 数据接入域（Tushare/质量门） | `tushare.**.*ErrorCode` |
| `3001`–`3999` | 运维读模型域 | `ops.*ErrorCode` |
| `4001`–`4999` | 能力单元（T6+） | `capability.*ErrorCode` |
| `5001`–`5999` | 流水线（T12+） | `pipeline.*ErrorCode` |
| `6001`–`6999` | 判断与验证（M3） | `judgment.*ErrorCode` |
| `7001`–`7999` | 报告存档 | `report.*ErrorCode` |
| `8001`–`8999` | 版本管理 | `version.*ErrorCode` |
| `9000+` | 保留 | — |

纪律：

1. **先复用**：参数错永远 400，查不到永远 404，冲突永远 409——不要为每个接口造码；
2. 只有"前端需要分支处理（文案/引导不同）"才新增业务码；
3. 码值**只增不改不复用**；删码 = 破坏性变更；
4. 错误码 enum 必须实现 `ErrorCode`，并写清"触发条件"Javadoc。

### 3.4 常用语义对照

| 场景 | code | 说明 |
|---|---|---|
| 参数格式/范围错 | 400 | 文案指明字段与合法范围 |
| 表/资源不存在 | 404 | 如未注册的数据表 |
| 已有编排在跑、重复触发、并发写 | 409 | 文案给"等它结束/稍后重试" |
| 依赖数据未回填 | 1003 | 引导用户去回填 |
| 状态机拒绝（如非 FAILED 作业重试） | 1004 | 文案说明当前状态 |
| 数据库文件锁/不可写 | 503 | 运维可操作提示（已统一处理） |
| 程序缺陷 | 500 | 只给 traceId，细节进日志 |

## 4. 出入参设计

| 规则 | 说明 |
|---|---|
| 请求体 `record` + 校验注解 | `record BackfillRequest(String start, String end)`；可空字段显式 `required=false` |
| 响应体 `record`（`*View`） | 不可变；字段名即契约；**不返回 Entity** |
| 领域只读 record 可直接作契约 | 如 `QualityReport`（质量门结果本身就是产品契约）：不复制一层 View，但该 record 一旦对外必须只增不改，变更走 §7 |
| 字段命名 camelCase | 与前端 TS 一致；禁止 `ts_code` 出现在 JSON（数据库列名不出 API） |
| 时间字段 | `LocalDateTime` → ISO `2026-11-24T15:30:00`；业务日期 → `"20261124"` 字符串 |
| 数值 | 用 JSON number；金额/比率保留 4 位小数（前端展示时格式化）；不要用字符串传数值 |
| 枚举 | 传**大写码字符串**（`SUCCESS`），不传中文、不传序号 |
| 布尔 | `true/false`；不要传 `0/1` |
| null 处理 | `spring.jackson.default-property-inclusion=non_null`：null 字段**不出现在响应里**。因此**必填字段永远不要返回 null**（会让前端类型与实际不符）；空集合返回 `[]` |
| 大字段 | 列表接口不返回 JSON 载荷/正文（只返回摘要 + 详情端点） |
| 动态列（如表格预览） | 允许 `Map<String,Object>`/`Record<string, unknown>`，但必须在 Javadoc/类型里标注"列名运行时决定" |

**可空性纪律**：后端非空字段 → 前端类型必须非可选。当前前端把 `rowsFetched`/`retryCount` 等非空字段写成 `?: number | null`，导致 81 处 `??` 兜底（见 05 §7 整改）。

## 5. 校验与错误文案

1. 格式/范围在 Controller 边界校验（`@Valid`、`@EnumCode`、`@Min/@Max`、`OpsParams`）；
2. 业务规则在 service 校验（`Asserts.isTrue(...)`）；
3. 文案模板：
   - 400：`"<字段> 必须为 <格式/范围>（当前 <值>）"`，如 `size 必须为 1~100（当前 0）`
   - 404：`"未知数据表: xxx"`（不要 `"not found"`）
   - 409：`"已有编排正在运行，请等待结束或查看当前进度"`
4. 禁止把上游英文错误直接透给用户；必须转成中文并保留 `traceId` 便于对账。

## 6. 幂等与并发

| 场景 | 做法 |
|---|---|
| 触发类 POST（编排/回填/质量门） | 返回 `accepted` + `runId`；已有运行中 → 409；同一个 `runId` 可查进度 |
| 重试类 POST | 只允许 FAILED 状态；否则 1004 |
| 反复点击 | 前端按钮 loading + 后端互斥（DB 标记 / 内存 `AtomicBoolean` + 启动重置） |
| 外部数据写入 | 唯一索引 + `ON CONFLICT`，重复执行结果一致 |
| 长任务 | 立即返回受理，进度用 GET 轮询；不在 HTTP 请求里同步跑分钟级作业（除非 CLI 入口） |

## 7. 契约演进

| 变更 | 允许? | 要求 |
|---|---|---|
| 新增可选字段 | ✓ | 前端类型同步（同一次提交） |
| 新增端点 | ✓ | — |
| 字段改名 | ✗ 直接改 | 新增字段 + 保留旧字段一个版本 + 前端切换后删除 |
| 字段类型变宽（int→long） | ⚠️ | 前端类型同步；注意 JS number 精度 |
| 删除字段 | ✗ | 先标 `@Deprecated` 并在 Javadoc 写替代，前端停用后再删 |
| 改变字段语义（单位/口径） | ✗ | 视为新字段 |
| 错误码变化 | ✗ | 只增不改 |

**前后端同步义务**：后端改了响应结构，必须在**同一个提交**里改 `frontend/src/api/types.ts` 与渲染处；否则视为未完成。

**契约文档**：`/v3/api-docs`（springdoc）是机器可读契约；新增/修改端点必须补 `@Operation(summary=...)`，复杂 DTO 补 `@Schema(description=...)`。前端 `types.ts` 目前手写镜像（22 个类型），若后续引入 `openapi-typescript` 生成，必须以生成物为准、手写层只保留视图派生类型。

## 8. 鉴权（2026-11-24 落地，多用户）

**认证**：登录返回**不透明随机令牌**（32 字节，Base64URL），前端放 `Authorization: Bearer <token>`。
服务端只存令牌的 SHA-256 十六进制哈希（`sys_user_session.token_hash`），令牌绝对有效期 = 配置天数
（`refine-loop.auth.token-ttl-days`，默认 7 天），到期需重新登录。

> 为什么不用 JWT：单服务器单体应用不需要跨服务验签，而会话表能立即撤销（登出/改密/停用/删号）；
> 对外契约仍是 `Authorization: Bearer`，令牌格式是实现细节。

| 规则 | 说明 |
|---|---|
| 公开端点 | 只有 `/api/health`、`/api/auth/login`、`/error`、`/swagger-ui/**`、`/v3/api-docs/**`；新增公开端点必须登记 `config/WebMvcConfig.PUBLIC_PATHS` |
| 未认证 / 令牌过期 / 已撤销 | `Result(code=401)`（HTTP 仍 200）；前端 `http.ts` 清本地令牌并跳登录页 |
| 已认证但无权限 | `Result(code=403)`；前端隐藏入口 + 后端兜底 |
| 权限声明 | 写动作标 `@RequirePermission(Permission.XXX)`；读动作默认为「登录即可」 |
| 角色 | 固定两档：`ADMIN`（账号管理 + 数据接入 + 系统开关）/ `USER`（只读行情 + 维护自己的偏好与自选股）；权限码见 `user.model.Permission` |
| 不做动态 RBAC | 只有两类真实角色，角色表/权限表/关联表没有业务需求；需要自定义角色时把 `UserRole.permissions()` 搬到 `sys_role` 表即可，接口声明不用改 |
| 个人数据隔离 | 所有「按用户」的接口（`/api/users/me/*`）用户 id 只来自登录态，**不接受请求体指定**；跨用户按 id 访问一律 404（不暴露存在性） |
| 禁止 | 把 token 放 query string；在日志打印明文令牌/密码；用 JWT 做「不可撤销」的长期会话 |

**密码**：PBKDF2-HMAC-SHA256（120000 次迭代 + 每用户随机盐），编码串 `pbkdf2$<iter>$<salt>$<hash>`；
校验用常量时间比较。首次启动（`sys_user` 为空）由 `config/UserBootstrapRunner` 创建管理员
`admin/admin123`，**生产必须用 `REFINE_LOOP_BOOTSTRAP_PASSWORD` 覆盖并首次登录后立即改密**。
