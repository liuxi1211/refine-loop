# 06 测试规范

> 现状基线：31 个测试类 / **232 个用例全绿**（`mvn -B test`，约 80s；其中 `ArchitectureRulesTest` 17 条、`SchemaConventionTest` 9 条为规范门禁），测试全部跑在**真实 SQLite 临时库**上（`target/test-db/`），HTTP 外部调用用 `MockRestServiceServer`，**不联网、不依赖开发库**。鉴权相关集成测试走真实登录接口拿令牌（`support/AuthTestSupport`），**不提供「关闭鉴权」开关**，避免回归时拦不住 401/403 退化。
> 强制等级：门禁为 `[L1]`（`mvn test` / `npm run build`）；测试设计与覆盖为 `[L3]`。

---

## 1. 测试分层（按被测对象选层，不按习惯选）

| 层 | 注解/工具 | 何时用 | 成本 | 现状占比 |
|---|---|---|---|---|
| 纯单元 | 无 Spring | 纯函数、解析、算法、枚举、工具类 | 毫秒 | 高 |
| 切片 | `MockMvcBuilders.standaloneSetup` / 手工装配 | Controller 契约、参数校验、错误码 | 百毫秒 | 高 |
| 数据层 | 真实 SQLite 临时库 + `SchemaTestSupport` | Mapper、批处理、类型处理器、schema | 1~5s | 中 |
| 集成 | `@SpringBootTest` + 内联 properties | 启动装配、跨层端到端（少量） | 5~15s | **≤10%**（现状 3 个 ✓） |

规则：

- **能用单元测的不用 Spring**；`@SpringBootTest` 每增加一个都要说明理由；
- 数据库测试必须用**真实 SQLite**（与生产同引擎），禁止 H2/内存假库；
- 不 mock 自己的 Mapper/Service（那是在测 mock）；只 mock 外部 HTTP（`MockRestServiceServer`）与时间（`MutableClock`）；
- Controller 测试用 standalone MockMvc，不起完整容器。

## 2. 命名与结构

| 对象 | 规则 | 例 |
|---|---|---|
| 测试类 | `<被测类>Test`；跨类场景用 `<场景>Test` | `IngestLogServiceTest`、`SchemaConventionTest` |
| 集成测试 | `<场景>IntegrationTest`，放 `it/` 包 | `OpsApiIntegrationTest` |
| 架构守卫 | `ArchitectureRulesTest`，放 `architecture/` | — |
| 用例方法 | **同一测试类内风格一致**；推荐中文场景式 `动作_条件_期望` | `upsertCrossesBatchBoundary`、`数据预览支持全列与分页并带LIMIT保护` |
| 断言消息 | 失败时能定位（`assertThat(x).as("第 %d 批的行数", n)`） | — |

**一个用例只验一件事**：一个 `@Test` 里 5 个不相关断言 = 5 个潜在失败原因混在一起。

**given/when/then 用空行分段**（不必写注释），准备夹具抽到 `@BeforeEach` 或 `support/`。

## 3. 目录与夹具

```
src/test/java/com/arthur/refineloop/
├── <与主代码同构的包>/        单元与切片测试
├── it/                        跨层集成（@SpringBootTest）
├── schema/                    DDL 与 schema 规范校验
├── architecture/              ArchUnit 依赖规则
└── support/                   夹具（无 Test 后缀）
    ├── SchemaTestSupport      临时库 + schema 执行 + sqlSessionFactory/mapper 构造
    ├── MutableClock           可控时钟
    ├── TestDates              固定日期常量
    └── TushareMockResponses   列式响应样本
```

| 规则 | 说明 |
|---|---|
| 测试包与主代码同构 | 便于回答"这个类测了吗"（现存 `ops`/`quality`/`ingest` 三个错位包已迁移） |
| 夹具集中 `support/`，无 `Test` 后缀 | 避免被 surefire 当测试类 |
| 临时库放 `target/test-db/`，随机文件名 | 并发/重复执行不互相污染；`mvn clean` 自动清理 |
| 测试不写仓库里的 `data/refine_loop.db` | 防止污染开发库 |
| 时间/随机可控 | 时间用 `MutableClock`；随机用固定种子或去掉随机 |
| 夹具数据就近构造 | 不要全局共享可变夹具对象（测试顺序依赖的根源） |

## 4. 覆盖要求

不设行覆盖率硬门槛（对 41 张表 + 外部接入的单人项目，覆盖率数字会诱导写"为覆盖而覆盖"的测试）。改为**清单式要求**：

| 变更类型 | 必需用例 |
|---|---|
| 新增公共组件（`common/**`） | 正常路径 + 至少 2 个异常/边界（空值、越界、格式错） |
| 新增 API 端点 | 成功 + 参数非法(400) + 资源不存在(404) + 冲突(409)（如适用） |
| 新增/改 schema | `SchemaSqliteTest` 计数与表清单 + `SchemaConventionTest` 命名/类型（自动） |
| 修 bug | **一条会失败的回归用例**（先红后绿），并在提交信息引用 issue |
| 改 SQL/索引 | 一条走该查询路径的用例 + 一条幂等/边界 |
| 改前端纯函数 | 边界值用例（0/负数/超长/非法格式） |
| 改并发/异步 | 至少一条"并发触发只成功一次"的用例（可测互斥） |

**禁止的测试**：`Thread.sleep` 等时序（用可注入 `Sleeper`/`Clock`）；依赖执行顺序；访问网络；依赖本机时区/语言（显式指定 `Asia/Shanghai`/`Locale.ROOT`）；`assertThat(true).isTrue()` 这类无意义断言。

## 5. 断言与失败信息

- 统一 AssertJ（`assertThat`），不用 JUnit 原生 `assertEquals`（消息可读性差）；
- 异常断言用 `assertThatThrownBy(...).isInstanceOf(ApiException.class).hasMessageContaining("...")`；
- 集合断言用 `containsExactly` / `extracting(...).containsExactly(...)`，避免只断 size；
- 时间断言用 `isEqualTo` 固定值，不用 `isBefore(now)`（不稳定）；
- 浮点比较用 `isEqualByComparingTo`（BigDecimal）。

## 6. 门禁与执行

提交前由提交者自觉执行（不设脚本封装）：

```bash
# 后端：编译 + 全量测试（含架构 / schema 规范校验）
mvn -B test

# 前端：类型检查 + 构建（改了 frontend/ 才需要）
cd frontend && npm run build

# 只跑某个类
mvn -B test -Dtest=IngestJobServiceTest
```

| 门禁 | 内容 | 失败即阻断 |
|---|---|---|
| 编译 | `mvn -q -DskipTests compile` | 是 |
| 后端测试 | `mvn -B test`（含 schema 校验、架构规则） | 是 |
| 前端构建 | `vue-tsc --noEmit` + `vite build` | 是 |
| 结构规则 | `ArchitectureRulesTest` | 是 |
| Schema 规范 | `SchemaConventionTest` | 是 |

**性能纪律**：`mvn test` 全量控制在 **90 秒**内；新增慢用例（>5s）需说明理由，或用 `@Tag("slow")` 隔离。

## 7. 测试数据与契约测试

| 对象 | 做法 |
|---|---|
| Tushare 响应 | `support/TushareMockResponses` 提供列式 JSON 样本（`fields/items`），新增接口时补一份 |
| 幂等键一致性 | `RegistrySchemaConsistencyTest`：注册表 fields ↔ schema 列逐列比对 |
| `ON CONFLICT` 冲突目标 | `UpsertConflictTargetTest`：冲突列必须等于幂等键 |
| schema 规范 | `SchemaConventionTest`：表/列/索引命名、类型白名单、审计列、注释 |
| 架构依赖 | `ArchitectureRulesTest`：包依赖矩阵、红线（JdbcTemplate/System.out/Entity 越界） |

契约测试（前后端类型一致性）目前靠人工 + 本规范；若引入 `openapi-typescript`，加一条"生成物与提交物一致"的检查。
