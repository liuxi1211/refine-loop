## 2. 统一响应与错误码

### 2.1 契约

```json
{ "code": 0, "msg": "ok", "data": { } }
```

| code | 含义 | 前端处理 |
|---|---|---|
| `0` | 成功 | 取 `data` |
| `400` | 参数/校验错误 | 展示 `msg` |
| `401 / 403` | 未认证 / 无权限 | 引导登录或无权限页 |
| `404` | 资源不存在 | 展示 `msg` / 空态 |
| `409` | 状态冲突（重复触发、并发写） | 提示刷新 |
| `413 / 415 / 429` | 体积过大 / 类型不支持 / 限流 | 通用提示 |
| `500` | 未预期异常（**只有这一档进 error 日志**） | 展示 `msg`（含 traceId） |
| `502 / 503 / 504` | 上游异常 / 依赖不可用 / 超时 | 可重试提示 |
| `1001~` | 业务码（1001 校验、1002 重复、1003 数据未就绪、1004 状态拒绝、1005 不支持） | 按业务文案 |

**HTTP 状态统一 200**，语义由 `code` 表达。HTTP 非 200 只代表「接口不可达/网关错误」，前端 `http.ts` 按网络错误处理。

### 2.2 用法

```java
// 成功
return Result.ok(view);
return Result.ok(ack, "已受理，后台执行中");
return Result.ok();                       // 无数据

// 失败（一般不要手写，直接抛异常让全局处理器兜底）
return Result.fail(CommonErrorCode.NOT_FOUND, "未知数据表: " + table);

// 转换数据
return Result.ok(items).map(PageResult::items);
```

### 2.3 新增错误码

1. 先判断能否复用：参数错一律 400、查不到一律 404、状态冲突一律 409；
2. 确实需要前端分支处理的业务失败 → 在所属域新建 `enum XxxErrorCode implements ErrorCode`，编码按段位（2xxx 数据接入、3xxx 能力单元、4xxx 流水线、5xxx 判断报告、6xxx AI、7xxx 调度）；
3. 文案写「用户看得懂的话」，不要写内部类名/SQL。

```java
public enum IngestErrorCode implements ErrorCode {
    TABLE_LOCKED(2001, "数据表正在被其他作业写入"),
    RANGE_INVALID(2002, "时间范围不合法");
}
```

### 2.4 业务异常：`ApiException`

```java
throw ApiException.badRequest("start 不能晚于 end");
throw ApiException.notFound("未知数据表: " + table);
throw ApiException.conflict("已有编排正在运行");
throw ApiException.dataNotReady("交易日历尚未回填");   // 1003，语义比 400 更准确
throw ApiException.of(IngestErrorCode.TABLE_LOCKED);
```

**什么时候不要包成 ApiException**：NPE、数组越界、数据库连不上、JSON 结构不符预期——这些是程序/环境问题，直接抛，由兜底处理器打 error + 堆栈。把它们包成 400 会让「线上 bug」伪装成「用户输错」。

## 3. 日志规范（异常分类 = 日志级别）

### 3.1 级别使用矩阵

| 场景 | 级别 | 示例 |
|---|---|---|
| 逐条明细、循环内进度、缓存命中、SQL 参数、方法入出参 | **debug** | `log.debug("表 {} 写入 {} 行", table, rows)` |
| 业务里程碑：作业开始/结束、编排完成、质量门结果、缓存刷新、字典加载 | **info** | `log.info("每日编排完成 runId={} 成功 {} 失败 {}", ...)` |
| 可恢复的降级：重试、数据缺失、跳过、局部失败、客户端参数错误 | **warn** | `log.warn("质量门告警：{} 缺失", table)` |
| 未预期异常 / 作业最终失败 / 数据不一致 | **error** | 只在 `GlobalExceptionHandler` 兜底、作业 FAILED 时使用 |

一句话：**默认写 debug，里程碑写 info，降级写 warn，只有明确的异常才 error**。判断标准：这条日志出现时，是否需要人半夜起来处理？是 → error；否 → 降级到 warn；只是记录过程 → debug。

### 3.2 traceId

- HTTP 入口由 `TraceIdFilter` 生成/透传（请求头 `X-Trace-Id` 合法则复用），写回响应头；
- 日志格式已包含 `[traceId]`（`logback-spring.xml`），业务代码不需要手动拼；
- 批处理/定时任务没有 HTTP 入口，自己绑定：

```java
try (var ignored = TraceContext.withRunId(runId)) {
    log.info("编排开始");
    for (TableDef table : tables) {
        try (var span = TraceContext.withSpan(table.tableName())) {
            writer.write(table);
        }
    }
}
```

- 异步线程/线程池：`AsyncConfig` 已挂 `MdcTaskDecorator`，`@Async` 方法自动继承提交方上下文；手写线程池时给 `ThreadPoolTaskExecutor.setTaskDecorator(new MdcTaskDecorator())`。

### 3.3 开关

- 生产（默认/`prod`）：`logging.level.com.arthur.refineloop=INFO` → 只留 milestone；
- 开发（`--spring.profiles.active=dev`）：`application-dev.yml` 把业务包与 Mapper 调到 DEBUG，可看到 SQL 与逐表进度；
- 临时排查单个类：`logging.level.com.arthur.refineloop.xxx=DEBUG` 无需重启配置中心（改 yml 重启即可，个人系统够用）。

### 3.4 禁止

- 不打 token/api-key（必要时 `MaskUtils.maskSecret`）；
- 不打完整请求体/响应体（全量数据落盘即事故）；
- 不在循环里 `log.info`（会淹没里程碑）；
- 不用 `System.out.println` / `printStackTrace`。

## 4. 常量组与字典（给前端下拉框）

### 4.1 为什么要有字典

以前前端写 `{ PENDING: '等待', RUNNING: '运行中' }`，后端 `Set.of("PENDING", ...)` 校验，改一个枚举要改三处。现在：**枚举是唯一事实源**，后端自动下发，前端 `DictSelect` / `DictTag` 直接消费。

### 4.2 新增一个字典（5 步）

```java
// 1) 登记类型编码（common.dict.DictTypes）
public static final String JOB_STATUS = "jobStatus";

// 2) 业务包里新建枚举，实现 DictEnum
public enum IngestJobStatus implements DictEnum {
    PENDING("PENDING", "等待", "idle"),
    RUNNING("RUNNING", "运行中", "run"),
    SUCCESS("SUCCESS", "成功", "ok"),
    FAILED("FAILED", "失败", "err"),
    SKIPPED("SKIPPED", "跳过", "idle");

    private final String code, label, color;
    // 构造器/字段略

    @Override public String dictType() { return DictTypes.JOB_STATUS; }
    @Override public String code() { return code; }
    @Override public String label() { return label; }
    @Override public String color() { return color; }
    @Override public int sort() { return ordinal() * 10; }
}

// 3) 启动即自动登记（DictService 扫描 com.arthur.refineloop 下所有 DictEnum 实现）
// 4) 入参校验
public record JobQuery(@EnumCode(IngestJobStatus.class) String status) { }

// 5) 展示文案
String label = dictService.labelOf(DictTypes.JOB_STATUS, job.getStatus());
```

要点：

- `code` 是落库/传输值，**发布后不可改**；`label` 可改（前端自动跟随）；
- `color` 可选，取值 `ok/warn/err/idle/run/off`，对应全局 `.chip` 色调；
- `dictType` 必须用 `DictTypes` 常量，禁止 `getClass().getSimpleName()`（改类名会静默改掉前端契约）；
- 枚举之间同一 `dictType` + `code` 重复 → **启动失败**（开发错误，故意的，避免前端出现两个同名项）；
- 动态字典（`DictProvider`）重复编码 → **告警并保留枚举/先到项**（外部数据错误不应让整个应用起不来）；
- 数据库/配置驱动的动态字典 → 实现 `DictProvider` 并声明为 Bean，会与枚举字典合并下发；`items()` 必须自己容错，不要抛异常。

> 已落地的真实示例：`tushare.ingest.IngestJobStatus`（`jobStatus`，作业状态）与 `tushare.ingest.WriteMode`（`writeMode`，落库模式）。前者同时被 `IngestController` 用于入参校验与错误提示，是「枚举 → 校验 → 前端下拉/标签」的完整闭环参考。

### 4.3 后端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/common/dicts` | 全部字典 `{type: [item]}`（首屏一次拉取） |
| GET | `/api/common/dicts/types` | 类型清单 |
| GET | `/api/common/dicts/{type}` | 单个字典（未知 type → 404） |
| POST | `/api/common/dicts/refresh` | 重建快照（改了枚举不想重启时用） |

字典项结构：`{ code, label, sort, color, enabled }`。

### 4.4 前端用法

```vue
<script setup lang="ts">
import { ref } from 'vue'
import DictSelect from '../components/DictSelect.vue'
import DictTag from '../components/DictTag.vue'

const status = ref<string>('')
</script>

<template>
  <!-- 下拉框：「全部」+ 枚举项；allowEmpty=false 时必选 -->
  <DictSelect type="jobStatus" v-model="status" placeholder="全部状态" />

  <!-- 状态标签：自动取 label + 语义色 -->
  <DictTag type="jobStatus" :code="'RUNNING'" />

  <!-- 只要文案/选项，不要组件 -->
  <!-- const { options, labelOf } = useDict('jobStatus') -->
</template>
```

- 字典只拉一次（Pinia store 合并并发请求），失败静默降级为「显示原始 code」；
- 新增枚举后前端**不需要改代码**，刷新页面即可（必要时 `POST /refresh`）。

### 4.5 通用枚举

`YesNoEnum`（1/0）、`EnableStatusEnum`（1/0 启用停用）、`SortOrderEnum`（asc/desc）。
数值开关建议后端用 `String` 接参 + `Enums.fromCode` 解析，避免前端 `"1"` 与 `1` 的类型问题。

## 5. 缓存（Caffeine）

### 5.1 三种用法怎么选

| 场景 | 用法 | 失效方式 |
|---|---|---|
| 跨模块共享的参考数据（股票列表、交易日历、行业映射、词表、方法版本、报告内容、字典、看板统计） | `CacheSpec` 登记 + `@Cacheable(cacheNames = CacheNames.XXX)` | TTL 自然过期 + 业务动作 `@CacheEvict` |
| 注解表达不了的（多表拼装、按条件决定是否缓存、需要主动失效） | 注入 `CacheTemplate` | `evict/clear` |
| 方法级临时缓存（几十秒、只在本类有意义） | `@LocalCache` / `@LocalCacheEvict` | TTL + 显式失效 |

原则（架构 §6.5）：**只缓存参考数据，不缓存业务事实**。事实以库表为准，保证可溯源。

### 5.2 具名缓存

```java
// 读：缓存名必须是 CacheNames 常量（CacheSpec 里已配好 TTL/容量）
@Cacheable(cacheNames = CacheNames.STOCK_LIST, key = "#tsCode", sync = true)
public StockBasic getStock(String tsCode) { ... }

// 数据变更后失效
@CacheEvict(cacheNames = CacheNames.STOCK_LIST, allEntries = true)
public void afterIngest() { ... }

// 集群/多key场景用编程式
public List<StockBasic> listAll() {
    return cacheTemplate.getOrLoad(CacheSpec.STOCK_LIST, "ALL", this::loadAllFromDb);
}
```

新增缓存必须**同时**改两处：`CacheNames` 常量 + `CacheSpec` 枚举（容量/TTL/说明），`CacheTest` 会校验两边不漂移。

### 5.3 方法级临时缓存

```java
@LocalCache(name = "suspendCalendar", ttlSeconds = 60, maxSize = 100, key = "#tradeDate")
public List<String> loadSuspendCodes(String tradeDate) { ... }

@LocalCacheEvict(name = "suspendCalendar", key = "#tradeDate")
public void refreshSuspendCodes(String tradeDate) { ... }
```

- `key` 支持 SpEL：`#p0`（第 1 个参数）、`#id`（参数名）、`#query.code`（属性）；留空则按参数拼接；
- 返回 `null` 也会被缓存（不会反复回源）；
- `sync = true`（默认）时同 key 并发只穿透一个线程，防击穿。

### 5.4 坑

- **同类自调用不生效**（Spring 代理机制），`this.method()` 不会走缓存；要么拆到另一个 Bean，要么用 `CacheTemplate`；
- 只能代理 `public`、非 `final` 方法；
- 别把会变的业务状态塞进缓存（比如「今天的作业进度」），这类走库/内存态；
- 缓存键要稳定：不要用对象默认 `toString()` 拼 key。

### 5.5 观测

`GET /api/common/cache` 返回每个具名缓存的大小、命中率、淘汰数；`DELETE /api/common/cache/{name}` 清空。

## 6. 分页与参数校验

### 6.1 分页

```java
@GetMapping
public Result<PageResult<IngestJobView>> page(
        @RequestParam(required = false) Integer page,
        @RequestParam(required = false) Integer size) {
    PageQuery query = PageQuery.of(page, size);      // null → 1/20；越界 → 400
    return Result.ok(ingestLogQueryService.page(query));
}
```

- `PageQuery.MAX_SIZE = 100`，不做静默截断（越界直接 400）；
- MyBatis-Plus 查询：`PageResults.toPage(query)` → `mapper.selectPage(...)` → `PageResults.of(mpPage)`；
- `PaginationInnerInterceptor` 必须注册（已在 `MyBatisPlusConfig`），否则 `IPage` 不会生成 LIMIT。

### 6.2 校验

```java
public record BackfillRequest(
        @NotBlank String mode,
        @EnumCode(IngestJobStatus.class) String status,
        @Min(0) @Max(100) Integer concurrency) { }

@PostMapping("/backfill")
public Result<Void> backfill(@Valid @RequestBody BackfillRequest request) { ... }
```

校验失败统一返回 `code=400`，`msg` 形如 `请求参数校验失败：mode: 不能为空`。

> 注意：`@RequestParam` / `@PathVariable` 上的约束注解（含 `@EnumCode`）需要 Controller 类上标 `@Validated` 才会触发；
> `@RequestBody` / `@ModelAttribute` 上的 `@Valid` 不需要。

## 8. 时间与 ID

- **取「现在」注入 `Clock`**：容器里已有 `appClock`（`TushareConfig`），单测可换 `Clock.fixed(...)` 或 `MutableClock`；不要直接 `LocalDate.now()`；
- **业务日期**（交易日、报告期）用 `yyyyMMdd` 字符串（`DatePatterns.DATE_COMPACT`）；
- **系统时间戳**用 `yyyy-MM-dd HH:mm:ss`（`DatePatterns.DATE_TIME`），与 SQLite `date_class=TEXT` 一致；
- ID：可读编号用 `Ids.timestampedId("R")`，需要排序主键用 `Ids.ulid()`，纯唯一用 `Ids.uuid32()`。

## 9. 线程与异步

- `@Async` 用容器默认 `applicationTaskExecutor`（虚拟线程 + MDC 透传 + CallerRuns 背压）；
- 专用并发控制用 `ThreadPools.virtualThreads("llm")`，并在 finally/生命周期结束时 `ThreadPools.shutdown(...)`；
- 虚拟线程下不要用 `ThreadLocal` 存大对象（用 `ScopedValue` 或显式传参）；MDC 已通过装饰器处理；
- CPU 密集任务（指标计算）用 `ThreadPools.fixed(name, CPU 核数)`，不要用虚拟线程。

## 10. 重试与外部调用

```java
TushareResponse response = RetryUtils.retry("tushare.daily", 3, Duration.ofSeconds(1),
        e -> !(e instanceof TushareParamException),   // 参数错误不重试
        () -> client.call(api, params));
```

- 只重试「可能自愈」的错误（网络、5xx、超时）；
- 退避带抖动，避免多线程重试风暴；
- 每次重试记 warn，最终成功记 debug。

## 11. 数据层约定

- 新表实体 `extends BaseEntity` → `created_at` / `updated_at` 由 `AuditMetaObjectHandler` 自动填充（`Clock` 口径，截断到秒）；
- 已有实体（`IngestLogEntity` 等）保持手工赋值，行为不变；
- **分页只有一套实现**：`PageQuery.of(page,size)` 校验 + `PageResults.of(...)` 组装；服务方法签名接收 `PageQuery`，不要再用 `(int page, int size)` 手工算 offset（2026-11-24 已统一）；
- **web 只依赖领域服务**：运维接口的读模型在 `ops` 域（`TableOpsService` / `StatsService` / `QualityOpsService` / `IngestOpsService`），Controller 不得注入 `*Mapper`（由 `ArchitectureRulesTest` 拦截）；
- 禁止在 service 写 SQL 字符串，禁止生产代码用 `JdbcTemplate`（架构 §3 强制约定）；
- 表结构/命名/类型规范见 [02-数据库与SQL规范](02-数据库与SQL规范.md)，由 `SchemaConventionTest` 守护。

## 12. 前端约定

- 统一用 `api/http.ts` 的 `get/post`：自动解包 `Result`、非 0 抛 `ApiError` 并 toast；

## 14. 从 0 写一个新接口（骨架）

```java
// 1) 错误码（可选）
public enum StockErrorCode implements ErrorCode { NOT_LISTED(5001, "标的不在股票列表内"); }

// 2) 入参 DTO（record + 校验注解）
public record StockQuery(@NotBlank String tsCode, @EnumCode(EnableStatusEnum.class) String enable) { }

// 3) 控制器：只做参数校验 + 调服务 + 包装返回
@RestController
@RequestMapping(CommonConstants.API_PREFIX + "/stocks")
public class StockController {

    private final StockService stockService;

    public StockController(StockService stockService) { this.stockService = stockService; }

    @GetMapping("/{tsCode}")
    public Result<StockView> detail(@PathVariable String tsCode) {
        Asserts.maxLength(tsCode, 32, "tsCode");
        return Result.ok(stockService.detail(tsCode));
    }

    @GetMapping
    public Result<PageResult<StockView>> page(
            @RequestParam(required = false) Integer page,
            @RequestParam(required = false) Integer size,
            @Valid StockQuery query) {
        return Result.ok(stockService.page(PageQuery.of(page, size), query));
    }
}

// 4) 服务：缓存 + 日志 + 业务异常
@Service
public class StockService {

    private static final Logger log = LoggerFactory.getLogger(StockService.class);

    @Cacheable(cacheNames = CacheNames.STOCK_LIST, key = "#tsCode", sync = true)
    public StockView detail(String tsCode) {
        log.debug("查询股票详情 tsCode={}", tsCode);
        StockBasicEntity entity = mapper.selectById(tsCode);
        if (entity == null) {
            throw ApiException.notFound("未知标的: " + tsCode);
        }
        return StockView.of(entity);
    }
}
```

前端对应调用：

```ts
const detail = await get<StockView>(`/api/stocks/${tsCode}`)
```

## 15. 账号、认证与权限（多用户）

> 2026-11-24 起，系统支持多用户。新增「按用户」的业务功能前先读本节。

### 15.1 能力与位置

| 能力 | 位置 | 一行示例 |
|---|---|---|
| 角色（固定两档） | `user.model.UserRole`（`ADMIN` / `USER`，实现 `DictEnum`） | `UserRole.ADMIN.code()` |
| 权限码 | `user.model.Permission`（`user:read`、`data:ingest`…，只增不改） | `Permission.DATA_INGEST.code()` |
| 登录 / 当前用户 | `web.user.AuthController` + `user.service.AuthService` | `POST /api/auth/login`、`GET /api/auth/me` |
| 账号管理 | `web.user.UserController` + `user.service.UserService` | `POST /api/users` |
| 交易偏好 / 自选股 | `web.user.UserPreferenceController` / `UserWatchlistController` | `PUT /api/users/me/preferences` |
| 鉴权拦截 | `web.auth.AuthInterceptor` + `@RequirePermission` + `CurrentUserContext` | 写动作加 `@RequirePermission(Permission.DATA_INGEST)` |
| 首次启动引导 | `config/UserBootstrapRunner` | 空库自动建 `admin/admin123`（生产用环境变量覆盖） |

### 15.2 给接口加权限

```java
// 读接口：默认「登录即可」，不标注解
@GetMapping
public Result<PageResult<UserViews.UserSummary>> page(...) { ... }

// 写/危险接口：声明所需能力；拦截器在认证之后判定（未登录 401、无权限 403）
@PostMapping("/{table}/run")
@RequirePermission(Permission.DATA_INGEST)
public Result<IngestTriggerAck> run(@PathVariable String table) { ... }
```

新增**公开**端点（无需登录）必须登记到 `config/WebMvcConfig.PUBLIC_PATHS`，否则会被 401 拦截。

### 15.3 新增「按用户隔离」的数据（照抄自选股）

1. 表加 `user_id BIGINT NOT NULL`，唯一键包含 `user_id`（如 `uk_<表>_user`），`data/entity` 继承 `BaseEntity`；
2. 写库前 `entity.touch(now())` 落审计时间；`user_id` 只能来自 `CurrentUserContext.require().id()`，**不接受请求体指定**；
3. 服务层所有查询 `eq(<Entity>::getUserId, userId)`；按 id 访问时若不属于当前用户 → `ApiException.notFound(...)`（404，不暴露存在性）；
4. 补一条「跨用户 404」负向用例（参考 `UserWatchlistServiceTest.usersCannotSeeEachOther`）。

### 15.4 前端

- 令牌存 `utils/authToken.ts`（`localStorage`），`api/http.ts` 统一注入 `Authorization` 并在 `code=401` 时清令牌跳登录；
- 登录态 / 权限判定走 `stores/auth.ts`（`isAuthenticated` / `isAdmin` / `hasPermission`）；
- 路由守卫：未登录跳 `/login`，`meta.permission` 不足回 `/overview`；后端仍会 403，前端只负责不展示入口。

### 15.5 首次启动与改密

- 空库首次启动创建 `admin / admin123`（日志 WARN 提示）；生产用 `REFINE_LOOP_BOOTSTRAP_USERNAME` / `REFINE_LOOP_BOOTSTRAP_PASSWORD` 覆盖，或用 `REFINE_LOOP_BOOTSTRAP_ENABLED=false` 关闭后自行导入；
- 改密 / 管理员重置 / 停用 / 删号都会撤销该用户全部会话，需重新登录；
- 密码策略：长度 ≥ `refine-loop.auth.password-min-length`（默认 8）、≤ 64；PBKDF2-HMAC-SHA256 编码串落库，不存明文、不进日志。
