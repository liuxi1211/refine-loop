# 05 前端编码规范

> 栈：Vue 3.5（`<script setup>` + TS 严格模式）· Vite 6 · Pinia 3 · Vue Router 4（hash 模式）· 纯手写组件（不引 UI 库/不引 axios）。
> 强制等级：类型检查（`vue-tsc`）为 `[L1]`；目录/命名/样式为 `[L3]`；ESLint 落地后部分转 `[L2]`（见 §11）。

---

## 1. 目录结构

```
frontend/src/
├── api/                 HTTP 客户端与契约（每个后端域一个文件）
│   ├── http.ts          唯一 fetch 出口：解包 Result、抛 ApiError、超时、toast
│   ├── types.ts         后端契约的 TS 镜像（字段名/可空性与后端一致）
│   └── tables.ts / ingest.ts / quality.ts / stats.ts / dict.ts
├── stores/              跨页面状态（Pinia，每域一个）
├── components/
│   ├── base/            通用无业务组件：BaseModal、StateBlock、StatusChip、ToastHost、ConfirmDialog、ToggleSwitch
│   └── domain/          跨页面复用的领域组件：DictSelect、DictTag、MiniBarChart
├── views/<feature>/     页面（index.vue）+ 页面私有组件（components/）
├── composables/         组合式函数（useXxx）
├── utils/               纯函数（format/status/…），无 Vue 依赖
├── styles/              tokens.css → base.css → components.css（index.css 统一入口）
└── router/              index.ts（hash 模式 + 兜底路由）
```

### 1.1 组件三分类（放错位置=评审驳回）

| 类型 | 判定 | 位置 | 命名 |
|---|---|---|---|
| 通用组件 | 不含业务概念，任何页面可用 | `components/base/` | 包装原生元素用 `Base*`（`BaseModal`）；纯展示用语义名（`StateBlock`/`StatusChip`） |
| 领域组件 | 含业务概念但**≥2 个页面**用 | `components/domain/` | 业务名（`DictSelect`、`JobStatusChip`） |
| 页面私有 | 只有 1 个页面用 | `views/<feature>/components/` | 业务名，无前缀（`TableDetailDrawer`） |

**现状偏差**（已登记）：19 个组件全部平铺在 `components/`，7 个页面私有组件与通用组件同级。整改策略是"改到即迁移"：动到某组件时顺手移到正确目录，不单独组织大规模搬迁提交。

### 1.2 目录阈值

| 对象 | 阈值 | 处理 |
|---|---|---|
| 单个 `.vue` | 300 行 | 拆子组件或抽 composable |
| 单个 store | 250 行 | 按域拆 |
| `components.css` | 1500 行 | 按域拆文件（card/table/form/modal/feedback），`index.css` 汇总 |
| `utils/` 单文件 | 200 行 | 按主题拆 |

## 2. 命名

| 对象 | 规则 | 例 |
|---|---|---|
| 组件文件 | PascalCase，**至少两个词** | `StateBlock.vue` ✓ / `state.vue` ✗ |
| 组件名与文件名 | 完全一致 | `StatusChip.vue` → `StatusChip` |
| composable | `useXxx.ts`，导出同名函数 | `useDict.ts` → `useDict()` |
| store | `stores/<域>.ts`，导出 `use<域>Store`，`defineStore('<域>')` | `useTablesStore` / id `'tables'` |
| api 文件 | 与后端域同名（`/api/ops/tables` → `tables.ts`） | — |
| api 函数 | `fetchXxx`（读）/ `runXxx`、`toggleXxx`、`retryXxx`（动作） | `fetchTables`、`runQualityCheck` |
| 类型 | PascalCase，**无 `I` 前缀**；interface 用于对象，type 用于联合/工具 | `TableMeta`、`ChipTone` |
| 常量 | `UPPER_SNAKE_CASE`，集中在 `src/constants/`（现状散落各文件，整改） | `STANDARD_TABLES` |
| CSS 类 | 新样式必须组件作用域（`<style scoped>`）或带模块前缀；**禁止新增 2~3 字符的通用缩写类** | `.table-detail__header` / `.rl-chip` |
| 事件 | `update:modelValue`（v-model）+ 语义事件（`action`、`retry`） | 禁止 `change`/`onClick` 混用 |

**近义名禁令**：`StateBlock` / `StatCard` 这种一字之差的名字，新组件必须避免；`BackfillDialog` 与 `BackfillWizard` 同构同模态，应合并为一个（已登记）。

## 3. SFC 结构

```vue
<script setup lang="ts">
/** 组件职责：一句话说清它渲染什么、何时发事件。 */
interface Props {
  table: string
  rows?: Record<string, unknown>[]
}
const props = withDefaults(defineProps<Props>(), { rows: () => [] })
const emit = defineEmits<{ retry: [] }>()
</script>

<template>
  <!-- 模板只做渲染与事件转发 -->
</template>

<style scoped>
/* 仅放本组件私有样式；通用样式进 styles/ */
</style>
```

| 规则 | 说明 |
|---|---|
| 顺序 `<script setup>` → `<template>` → `<style>` | 统一，减少 diff 噪声 |
| props 用 TS 泛型 + 抽 `interface Props`（≥3 个 props 时） | 现状全部内联字面量，无法复用/文档化（整改） |
| `emits` 统一 call-signature | 禁止与元组写法混用（现状 6 处两种写法） |
| 禁止 `any`、禁止 `@ts-ignore`/`@ts-expect-error` | 用 `unknown` + 收窄 |
| 禁止 `v-html` | 全站无富文本需求；将来需要必须走白名单净化 |
| 禁止 `console.*` | 用 UI 的 toast/状态区展示 |
| 禁止静态行内 `style` | 仅允许运行时计算值（进度宽度、状态色）；静态样式一律入类 |
| 禁止在组件里 `import ../api/xxx`（除 `http.ts` 的错误工具） | 数据获取只经 store/composable（ESLint `no-restricted-imports` 落地后强制） |
| 定时器/监听必须有清理 | `onUnmounted` 清 `setInterval`/`addEventListener`；页面隐藏时暂停轮询 |

## 4. 状态管理（Pinia）

| 规则 | 说明 |
|---|---|
| store 只放**跨页面共享**状态 | 页面局部状态用 `ref`；不要把表单临时值塞进 store |
| 一个域一个 store，id = 文件名 | `'tables'` / `'ingest'` / `'quality'` / `'stats'` / `'dict'` / `'ui'` |
| 异步状态必须是三态 + error | `loading` / `loaded` / `error: ApiError \| null`，并由**统一封装**生成（见下） |
| 动作命名 | `fetchXxx` / `runXxx` / `toggleXxx`；同一动作不许两个名字 |
| 禁止 store 之间循环依赖 | 组合方向单向：`ui` ← 其它；域 store 不互相 import |
| 轮询 | 只允许在页面/组件层控制生命周期（`onMounted`/`onUnmounted`），store 不自己开定时器 |

**异步样板必须收敛**：现在 7 处同构的 `if (!background) loading…try…catch…finally` 必须抽成 `composables/useAsyncResource.ts`：

```ts
const tables = useAsyncResource(fetchTables, { initial: [] })
tables.data.value      // 数据
tables.error.value     // ApiError | null
tables.run({ silent: true })   // 统一处理 loading/错误
```

在此之前，新代码禁止再复制这套 17 行样板。

## 5. API 层

```ts
// 唯一出口，禁止在别处 fetch
export async function fetchTables(options: FetchOptions = {}): Promise<TablesOverview> {
  return get<TablesOverview>('/api/ops/tables', undefined, options)
}
```

| 规则 | 说明 |
|---|---|
| 只有 `http.ts` 调 `fetch` | 现状 1 处，保持；禁止引入 axios |
| 路径写**绝对路径** `/api/...` | 由 Vite dev proxy / Nginx 转发；不在 api 层拼 baseURL |
| 选项统一对象形态 `{ silent?, signal? }` | 禁止位置布尔 `fetchX(silent = false)`（现状 3 套签名，整改） |
| 错误统一 `ApiError` | `kind: 'network' \| 'timeout' \| 'http' \| 'business'` + `code`；`describeError` 出文案 |
| 成功语义 | `code===0` → 返回 `data`；`data` 缺失时返回 `null` 而不是 `undefined`（类型上显式 `T \| null`） |
| 超时 | 默认 15s；长任务端点（质量门/回填）单独设置（30~90s） |
| POST 无 body 时不发 `{}` | 现状 `post()` 恒发 `{}`，会让"无 body"与"空对象"不可区分（低风险，整改项） |
| 类型契约 | `types.ts` 与后端 `*View` 一一对应；字段名/可空性必须一致（§7） |

## 6. 样式

### 6.1 分层

| 文件 | 只放 | 禁止 |
|---|---|---|
| `tokens.css` | CSS 变量（颜色/字体/阴影/圆角/间距/字号/z-index）+ reset | 业务类、布局类 |
| `base.css` | 应用骨架（sidebar/topbar/content）、页面抬头、动画、响应式断点 | 组件皮肤 |
| `components.css` | 组件类（card/btn/chip/table/modal/drawer/…） | 页面专属的一次性覆盖 |
| 组件 `<style scoped>` | 组件私有、只在组件内有意义的样式 | 全局选择器 |

**新增 token** 时同步补进 `tokens.css` 并在本规范 §6.3 说明；禁止在组件里写裸色值（`#fafbfc`）与裸字号（`13.5px`）。

### 6.2 规则

1. **禁止静态行内 style**（现状 111 处，`DataOverview.vue`/`TableDetailDrawer.vue` 各 21 处，整改）；动态 `:style` 仅用于"值由运行时计算"（进度条宽度、状态色）。
2. 单位统一 `px`（当前全 px）；字号/间距/圆角必须来自 token，禁止 16 档字号并存。
3. 断点统一 4 档：`≥1440`、`1280`、`1024`、`768`；新增组件必须考虑 1280 与 768 下的表现（抽屉/表格宽度）。
4. 类名：新组件用 `scoped` 或 `rl-` 前缀；**不得新增** `.tr`/`.t`/`.s`/`.d` 这类 1~2 字母类（现有冲突：`.tr` 同时是开关轨道与统计卡脚注）。
5. 禁止 `!important`（除非覆盖第三方，且需注释说明）。
6. 删除死类（约 9 条已确认无引用），不留"以后可能用"的样式。

### 6.3 现状 token 缺口（整改项）

字号（16 档 → 6 档 `--fs-xs/sm/md/lg/xl/2xl`）、间距（`--sp-1..8`）、圆角（7 档 → `--r-sm/md/lg`）、z-index（5 个裸值 → `--z-*`）。在补齐之前，新样式只用 `tokens.css` 已有变量。

## 7. 类型契约

| 规则 | 说明 |
|---|---|
| 后端非空字段 → 前端非可选 | 现状 `rowsFetched?: number \| null` 与后端 `long` 不符，导致 81 处 `??`（整改） |
| 后端可空字段 → `T \| null`（显式） | 不要用 `?` 静默省略 |
| 日期 | 业务日期 `string`（`yyyyMMdd`），系统时间 `string`（ISO）；如需强类型用品牌类型（整改项） |
| 枚举 | 用后端码的联合类型（`'PENDING' \| 'RUNNING' \| …`），不要 `string` |
| 契约变更 | 后端改字段 → 同提交改 `types.ts` + 渲染处 |
| 生成（可选） | 若引入 `openapi-typescript`：`types.gen.ts` 为唯一契约源，手写层只做 `Pick/Omit` 派生 |

## 8. 字典与文案

- 状态/类型/结果的中文文案**不允许前端硬编码**：用 `DictTag`/`useDict`（后端 `DictEnum` 下发），或至少集中在 `utils/status.ts` 且与后端 `DictTypes` 一一对应。
- 现状矛盾：字典链路（`api/dict.ts` → `stores/dict.ts` → `DictSelect`/`DictTag`，约 257 行）**零引用**，页面仍用 `switch` 硬编码中文。二选一（ADR）：
  - **A（推荐）**：启用字典链路，`status.ts` 只保留 `tone` 计算；
  - B：删除字典链路，明确"前端自持文案"并在本规范登记例外。
  **禁止第三态**（既有死代码又有硬编码）。
- 数字类文案（"41 张表""≤2 个交易日"）必须来自接口或单一常量，禁止在 3 个页面各写一遍（现状已出现阈值文案与代码判定不一致的真实 bug）。

## 9. 环境与构建

| 项 | 规则 |
|---|---|
| 环境变量 | `VITE_*` 前缀；`.env.development` / `.env.production` 提交示例（`.env.example`），真实值不入仓 |
| API 地址 | 开发用 Vite proxy（只保留 `/api` 一条），生产用 Nginx 同源反代；禁止把 `127.0.0.1:8080` 写进组件文案 |
| base | 默认 `/`；若部署到子路径，必须 `base` 从 env 读取（现在产物只能挂根路径） |
| port | `strictPort: true`（避免静默换端口导致 README 与实际不一致） |
| 产物 | `frontend/dist/` 不入仓；发布由部署脚本构建 |
| 构建门禁 | `npm run build` = `vue-tsc --noEmit` + `vite build`；类型错不许发布 |
| Node 版本 | `package.json` 增加 `engines` + `.nvmrc`（Node 22 LTS） |

## 11. 工具链（落地计划，按顺序）

1. **`.editorconfig`**（已完成）：缩进/换行/字符集基线；
2. **ESLint flat config**：`eslint` + `eslint-plugin-vue` + `typescript-eslint` + `eslint-config-prettier`；关键规则：`vue/multi-word-component-names`、`no-console`、`no-restricted-imports`（组件禁直接 import `../api/*`）、`@typescript-eslint/no-explicit-any`；
3. **Prettier**：只格式化，规则与 ESLint 不冲突；
4. **Stylelint**：`selector-class-pattern`（约束新类名）、`no-descending-specificity`；
5. **tsconfig 收紧**：`noUnusedLocals`/`noUnusedParameters` = true，`vueCompilerOptions.strictTemplates` = true；
6. 以上全部在提交前自行执行一遍（不设脚本封装，靠自觉）。

在工具落地前，`npm run build`（类型检查）是唯一机械门禁——意味着 §3 的模板级规则（未知 prop、多余 attribute）现在拦不住，评审必须人工看。

## 12. 自查清单

- [ ] 组件在正确目录（base/domain/views-private），命名 ≥2 词且与文件同名；
- [ ] `<script setup>` + TS props/emits，无 `any`/`v-html`/`console`；
- [ ] 数据获取经 store/composable，错误进 `StateBlock`；
- [ ] 无静态行内 style、无裸色值/字号，动态样式仅限计算值；
- [ ] 定时器在卸载时清理；
- [ ] 类型与后端契约一致（可空性/枚举/日期格式）；
- [ ] 文案不硬编码枚举中文，数字不硬编码业务口径；
- [ ] 新增/改动有对应测试（或说明为何不测）。
