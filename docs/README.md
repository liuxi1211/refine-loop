## 5. 文档维护规则

- 改代码影响公共能力/结构/契约 → 同一次提交更新对应文档（见 07 §8）；
- 规范与代码冲突时，以代码事实（`db/schema.sql`、`pom.xml`、门禁测试）为准，并提交一次规范修正；
- 改规范条款 → 直接改 `.claude/rules/` 的对应文件（**规范唯一载体，`docs/` 不留副本**），并在附录「变更历史」记一行；
  `KnowledgeBaseFilesTest` 会拦：死链、丢掉 `paths` 的规则、没登记到 `CLAUDE.md` 加载地图的规则、以及 `docs/` 下重新冒出的规范副本；
- `原型图/`、`旧项目参考-*/`、`开源金融类ai插件参考/` 属参考资料，不参与规范约束（后两者不入仓）。
