# 开发任务计划（AI 辅助开发拆分版）

> 文档版本：v1.0
> 文档性质：开发任务拆分计划，每个任务 = 一个可直接交给 AI 执行的 PRD
> 上游文档：《项目整体介绍与设计总纲》v2.0、《技术架构与模块设计》v1.1、《核心能力体系设计详案》v1.1、《Tushare接口对接手册》、《前端设计详案》v1.1
> 使用方式：按编号顺序执行；每个任务开工前，将「任务 PRD + 引用的设计文档章节」一起交给 AI；任务完成后按验收标准逐条核验，通过才进入下一任务

---

## 0. 总体说明

### 0.1 拆分原则

1. **严格按依赖排序**：数据地基 → 框架骨架 → 最小闭环 → 横向铺开 → 联调验收，与《核心能力体系设计详案》第 4 章「M1 内部落地顺序」一致；
2. **每个任务可独立验证**：每个 PRD 都有明确的「验收标准」，全部为可运行、可观测的核验项，不含主观描述；
3. **任务粒度对齐 AI 上下文**：单个任务的代码量控制在 AI 一次会话可完成并自测的范围内；跨任务只通过「数据库表 + 接口契约 + 包边界」耦合，不通过「记忆」耦合；
4. **设计文档是唯一事实源**：任务 PRD 只写「做什么、做到什么程度算完」，实现细节一律引用设计文档章节，避免两处描述漂移。

### 0.2 任务状态标记约定

| 标记 | 含义 |
|---|---|
| 前置 | 必须完成的任务编号 |
| 交付物 | 本任务产出的代码/配置/文档 |
| 验收 | 逐条可核验的标准，AI 完成后自查、人工抽查 |
| 禁改 | 本任务不得触碰的既有内容（防止 AI 越界修改） |

## 一、Phase A：项目地基（T1~T5）

> **数据库引擎迁移说明（2026-11-24）**：本阶段数据库已由 **MySQL 8 迁移为 SQLite 3**（`sqlite-jdbc` 3.50.3.0，嵌入式单文件库）。下文任务原文中「空 MySQL 库/连接 MySQL」等步骤已不适用：建库建表由应用启动期 `SqliteSchemaInitializer` 自动完成（schema 全 `IF NOT EXISTS`，幂等），库文件默认 `./data/refine_loop.db`。迁移理由、变更清单与已知取舍见《T2-T5 实施报告与偏差记录》**D12** 与**第七节**。

## 六、执行纪律（给每一个开发会话的约束）

1. **开工动作**：只加载当前任务 PRD + 它引用的设计文档章节，不携带其他任务的实现细节上下文；
2. **边界纪律**：`禁改` 清单之外的内容也不做顺手重构；发现设计文档与实现冲突时，停下回报，不得静默自行改设计；
3. **验收纪律**：验收清单逐条执行并在会话中留证据（命令输出/测试结果）；任何一条不通过不得声明任务完成；
4. **版本纪律**：新增依赖先登记架构文档 §1 版本基准清单；新增 logic_tag 先评估归因统计连续性（能力详案 9.1）；
5. **检查点**：T11（最小闭环）与 T18（P1 端到端）是强制人工确认检查点，不通过不进入下一 Phase。
