## 0. 设计起点：用户如何使用这个系统

### 0.1 用户画像

单人使用。A股个人投资者，**不具备专业分析能力**（这是前端设计的核心约束：系统替用户做分析，前端负责把分析结果「翻译」给用户），每天可用时间集中在盘后与周末，对系统的期望是「越用越准、可信任、可回溯」。

### 0.2 三类使用场景（一切页面设计的出发点）

| 场景 | 时间 | 心态 | 期望耗时 | 对应模块 |
|---|---|---|---|---|
| 晚间速览 | 每晚流水线跑完后 | 累了一天，只想知道「今天有什么需要我注意的」 | 5~10 分钟 | 今日简报、候选池、个股详情 |
| 周末复盘 | 周末下午 | 有耐心，想搞清楚「最近判断准不准、哪里错了」 | 30~60 分钟 | 复盘中心、判断与验证 |
| 偶发查证 | 任意时刻（如在券商软件看到一只票心动了） | 「这票系统分析过吗？结论是什么？」 | 1~2 分钟 | 全局搜索 → 个股详情（未分析标的可见历史淘汰原因或一键发起手动分析，M1 即闭环） |

### 0.3 首页的第一性原理

**首页不是数据看板，是「今日简报」。** 打开系统 30 秒内必须回答四个问题：

1. 流水线跑完了吗？
2. 我的持仓出事了吗？（M2；风险优先级最高）
3. 候选池有什么变化？
4. 有没有到期的判断等着我处理？（M3）

## 1. 四条设计原则

| # | 原则 | 落地方式 |
|---|---|---|
| 1 | **结论先行，细节折叠**（金字塔） | 每页第一屏只放「直接告诉我答案」的结论；方法论细节全部折叠在第二层。用户不懂分析，前端只展示系统分析的结论 |
| 2 | **状态驱动，不是数据驱动** | 页面围绕「变化与需要注意的事」组织（新进/异动/到期/失效），不是围绕数据表 |
| 3 | **溯源是信任的根基** | 每个数字可追溯（hover 显示来源事实表与日期）；每个判断可回看历史轨迹 |
| 4 | **决策边界永远清晰** | 全站禁止「买入/卖出」字样；用「纳入观察/移出观察/继续观察」等观察词汇。唯一例外是 M2 持仓建议卡：使用「维持持有/收缩仓位/移出持仓」参考措辞，且必须挂 DecisionGateHint 角标。总纲「人工决策闸门」在 UI 层的体现 |

## 2. 信息架构与导航

```
今日简报（首页 /dashboard）            ← M1 目标形态（T21 落地）
├── 候选池（/candidates）
├── 持仓（/positions，M2）
├── 判断与验证（/judgments）
├── 复盘中心（/review，M3）
└── 系统中心（/system：运行看板 / LLM 用量 / 配置）
个股详情（/stock/:code，不占一级导航，全局搜索直达）

当前已实现（T10 后、T12 前，数据中心形态）：
/data/overview   数据总览（表健康度 + 首启引导 + 表详情抽屉）
/data/jobs       接入与回填（编排进度 / 作业历史 / 质量门 ?tab=quality）
/profile、/users 账户与用户管理
```

> **过渡期约定**：M1 的分析端页面尚未落地，为避免「假页面」，未上线模块在侧栏显示为静态说明而不是可点击入口；
> 路由已按 `/data/*` 分区，为后续 `/dashboard`、`/candidates`、`/judgments` 留出命名空间（旧路径保留 `alias` 以免书签失效）。

- **全局搜索框**置顶常驻（代码/名称模糊搜索，回车直达个股详情）——偶发查证场景的入口必须一步直达；
- 左侧一级导航 6 项；未上线模块显示占位入口（空态页写明「M2 上线」），保持产品骨架完整可见；
- 响应式最低要求：1366px 桌面为主，允许在移动端浏览器浏览简报页与报告页不破版（Element Plus 栅格适配，不做专门移动端交互）。

## 3. 页面详细设计

### 3.1 今日简报（首页）——「今天我要注意什么？」

```
┌─────────────────────────────────────────────────────────┐
│ [今日一句话]  今天最重要的一件事（LLM 提炼，1~3 行）          │
├──────────────┬──────────────────────────────────────────┤
│ 流水线状态卡   │ 持仓关注区（M2）                           │
│ P1 ✓ 用时42m  │ ⚠ 2只持仓触发异动分析 → 查看详情             │
│ 0失败 3降级    ├──────────────────────────────────────────┤
│ LLM费用 ¥0.8  │ 候选池变化                                 │
│              │ 🆕新进 3只（展开列表）｜ 连任 7只 ｜ 移出 2只   │
├──────────────┴──────────────────────────────────────────┤
│ 待办事项（M3 实化）                                        │
│ □ 2条判断今日到期  □ 1条判断命中验证规则待归因                │
└─────────────────────────────────────────────────────────┘
```

| 功能点 | 说明 |
|---|---|
| 今日一句话 | 每日流水线 S5 后由系统汇总生成并持久化，前端只读；点击可展开当日完整摘要 |
| 流水线状态卡 | 最近一次 P1 run 的状态/耗时/失败降级计数/当日 LLM 费用估算；失败时整卡变警示色但**不弹窗打扰** |
| 候选池变化 | 与昨日对比的新进/连任/移出分组，点击进候选池页 |
| 待办事项 | M1 显示流水线异常待处理；M3 显示到期判断与验证命中，可点击直达 |

> **首启引导（过渡期必备，已在数据总览实现）**：所有表既无行数也无最新日期时，隐藏「一键每日增量」，改为「开始初始回填」横幅 + 回填向导。
> 理由：空库点每日增量只会拉回几天数据，健康度却全绿，用户会误判「数据已就绪、可以开始分析」。这条引导在今日简报落地后原样迁移到首页。

### 3.2 候选池——「今天可以重点看哪些票？」

| 功能点 | 说明 |
|---|---|
| 日期切换 | 默认最近交易日，可回看历史每一天的池子 |
| TopN 列表 | 评分从高到低；每行：代码/名称/总分/方向判断 badge/置信度/新进连任标记 |
| 因子明细展开 | 行展开显示各因子得分明细（趋势/成长/估值/红旗计数各贡献多少），用户必须能理解「为什么它在榜上」 |
| 跳转 | 行点击 → 个股详情页 |

### 3.3 个股详情——「这只票到底怎么样？」（信息密度最高页面）

```
┌─────────────────────────────────────────────────────────┐
│ 000001.SZ 平安银行   20261122 分析          [历史轨迹▾]    │
├─────────────────────────────────────────────────────────┤
│ ■ 30秒结论（置顶，不折叠）                                 │
│   方向：看多占优（置信度：中）  有效期：60天                  │
│   关键价位：支撑 10.85 ｜ 压力 12.40 ｜ 失效 10.40          │
│   核心逻辑：营收增速回升 + 估值分位低位（标签：业绩改善、估值修复）│
│   → [查看完整判断记录]                                     │
├─────────────────────────────────────────────────────────┤
│ ▸ 业务速览（默认收起）                                      │
│ ▸ 财务质量（默认收起）                                      │
│ ▸ 估值解读（默认收起）                                      │
│ ▸ 多空对照（默认收起，展开后左右双栏）                        │
├─────────────────────────────────────────────────────────┤
│ ▸ 历史判断轨迹（M2+）：历次分析的时间线与改判对比               │
└─────────────────────────────────────────────────────────┘
```

| 功能点 | 说明 |
|---|---|
| 30 秒结论 | 数据直接来自主判断 Schema（判断与验证流水线产物），只读渲染 |
| 分维度折叠区 | 每个维度渲染对应 interpret 单元的报告 markdown；30 秒结论永远展开，其余默认收起 |
| 数字溯源 | 报告内数字（facts_used 引用的指标）带下划虚线样式，hover 弹层显示「指标名 / 数值 / 来源表 / 交易日 / 采集时间」 |
| 多空对照 | 多空论证展开后左右双栏对照（共享事实底座表 + 对照判断表），忠实还原 bull_bear_case_builder 的输出结构 |
| 历史轨迹（M2+） | 同一只票历次报告与判断的时间线；改判时高亮显示「上次看多 → 本次改判」及原因 |
| 手动单股分析（M1） | 按钮触发单股深度分析任务（`POST /api/stocks/{code}/analyze` → trigger 表，仅执行 S3/S4），进行中显示进度；LLM 用量计入日预算熔断——「偶发查证」场景在 M1 即闭环 |
| 未分析标的空态 | 搜索命中未分析股票时：该票近 90 天被流水线评估过 → 展示评估时间与淘汰原因（红旗明细，数据源 `pipeline_run_item` 摘要）；从未评估 → 展示「系统未分析过该股」并提供手动分析入口 |
| 判断时效 | 判断已过 `expire_at` 时，30 秒结论整卡灰显并标注「判断已到期，待重估」，防止把过期判断当现役结论 |

### 3.4 判断与验证——「系统说过的话，兑现了吗？」

| 功能点 | 说明 | 里程碑 |
|---|---|---|
| 判断列表 | 状态筛选（进行中/已命中/已失效/已到期）+ 方向筛选 + 逻辑标签筛选；每行：代码/方向/有效期/置信度/当前验证状态 | M1 只读列表 |
| 判断详情 | 当初完整逻辑（thesis）、key_levels、verification_rules 清单及各自执行状态 | M1 展示规则，M3 实化状态 |
| 验证命中流（M3） | 到期/命中的判断进入「待归因」队列；归因报告生成后关联展示 | M3 |
| 判断轨迹不可变提示 | 所有记录只读 + 「已标注失效」灰显样式，强化总纲 5.1「不可删除不可篡改」的用户感知 | M1 |

### 3.5 复盘中心——「这系统靠谱吗？我该怎么调它？」（M3/M4）

| 功能点 | 说明 |
|---|---|
| 按标签命中率 | 「估值修复类逻辑 78% 命中，事件驱动类 40%」式分组统计——直接告诉用户该信哪类结论 |
| 版本对比 | 按方法版本分组的效果对比（迭代前后胜率/偏差分布），支撑总纲 5.4 人工迭代 |
| 偏差分布 | 四类偏差（价位偏离/方向偏离/逻辑失效/到期验证）的分布与典型样本列表 |
| 周报/月报（M4） | 定期全景复盘报告阅读页（复用报告渲染组件） |

### 3.6 持仓管理——「我的钱怎么样了？」（M2）

| 功能点 | 说明 |
|---|---|
| 持仓录入 | 纯手工表单：代码/成本价/仓位/买入日期；不对接券商 |
| 每日持仓简报 | 逐只卡片：当日涨跌/关键位距离/是否触发异动；卡片状态色（正常/关注/警示） |
| 异动分析入口 | 触发异动的持仓卡片内嵌异动归因摘要 + 「查看深度分析」 |
| 持有建议卡 | 维持持有/收缩仓位/移出持仓**参考** + 观察条件；卡片明示「仅供参考，决策由您做出」并挂 DecisionGateHint（设计原则 4 的唯一豁免场景） |

### 3.7 系统中心——「后台还活着吗？花了多少钱？」

| 功能点 | 说明 |
|---|---|
| 运行看板 | pipeline_run 历史列表 + run 详情（阶段耗时、标的级成功/降级/失败明细） |
| LLM 用量 | 按日/按单元的调用次数、token 量、费用估算——个人预算约束下必须天天可见 |
| 手动触发 | 触发流水线/补跑指定日期；进行中的 run 显示阶段进度条 |
| 配置只读 | 当前方法版本、单元版本清单、评分权重、受控词表（M1 全部只读） |

## 4. 全局组件与布局

| 组件 | 设计 |
|---|---|
| Layout | 左侧固定导航（可折叠）+ 顶部栏（全局搜索 + 当前方法版本 badge）+ 内容区面包屑 |

| DecisionGateHint | 涉及建议类内容统一挂「仅供参考，最终决策由您做出」角标（设计原则 4 的组件化） |

## 5. 状态管理（Pinia）

| Store | 职责 | 关键 state |
|---|---|---|
| `useAuthStore` | 登录态、token、登出 | token, user |
| `useDashboardStore` | 今日简报页数据（一次聚合接口） | todayBrief, pipelineStatus, todos |
| `useCandidateStore` | 候选池（按日期） | date, list, factorDetail |
| `useStockStore` | 个股详情（报告+判断+溯源数据） | currentCode, report, judgment, traceHistory |
| `useJudgmentStore` | 判断列表与详情（筛选条件） | filters, list, detail |
| `usePositionStore`（M2） | 持仓列表与简报 | positions, dailyBrief |
| `useSystemStore` | 运行看板、LLM 用量、配置 | runs, usage, methodVersion |

数据获取约定：页面级数据用一次性聚合接口（如简报页 `/api/dashboard/today`），避免首页串行发多个请求；个股详情按需懒加载（结论先行，折叠区展开时才请求对应报告段）。

## 6. API 对应总表

前端依赖的后端接口（`/api` 前缀，鉴权 JWT）。端点契约以《技术架构与模块设计》4.7 节为**唯一事实源**，本表仅为页面 → 端点映射视图：

| 页面 | 端点 | 说明 |
|---|---|---|
| 登录 | POST /api/login | 返回 JWT |
| 今日简报 | GET /api/dashboard/today | 简报聚合：流水线状态+候选变化+待办+今日一句话 |
| 运行 | GET /api/runs、GET /api/runs/{id}、POST /api/runs/trigger | 架构文档已有 |
| 候选池 | GET /api/candidates?date= | 架构文档已有 |
| 因子明细 | GET /api/candidates/{code}/factors?date= | 评分明细展开 |
| 个股详情 | GET /api/stocks/{code}/facts?date=、GET /api/stocks/{code}/reports?date= | 事实表 + 报告段列表 |
| 报告 | GET /api/reports?date=、GET /api/reports/{id}/content | 架构文档已有 |
| 溯源 | GET /api/facts/{factId} | 单条事实溯源（fact_used 来源） |
| 手动单股分析 | POST /api/stocks/{code}/analyze | 触发单股 S3/S4 深度分析（M1） |
| 判断 | GET /api/judgments?status=&tag=&direction=、GET /api/judgments/{id} | M1 只读 |
| 复盘（M3） | GET /api/stats/tag-hit-rate、/api/stats/version-compare、/api/stats/deviation | 效果统计 |
| 持仓（M2） | GET/POST/DELETE /api/positions、GET /api/positions/brief?date= | 手工 CRUD |
| LLM 用量 | GET /api/usage/llm?from=&to= | 按日/按单元 |
| 配置 | GET /api/method-version、GET /api/tags | 架构文档已有 |

接口约定：统一 `Result{code,msg,data}` 包装；列表接口统一分页参数；日期统一 `yyyyMMdd`。

## 7. 技术实现要点

| 项 | 决策 |
|---|---|
| 框架 | Vue 3 + Vite + TypeScript + Element Plus + Pinia + Vue Router |
| 报告渲染 | markdown-it + 自定义渲染规则：识别溯源标记语法（约定 `[[metric|value]]` 形式，报告生成端写入）转为 TraceTooltip 组件；渲染前 sanitize 防注入 |
| 图表 | ECharts（按需引入），M1 仅候选池因子条形图与运行看板耗时图，不做大屏 |
| 请求层 | Axios 实例统一拦截：JWT 注入、401 跳登录、错误 toast、取消重复请求 |
| 构建 | `npm run build` 纯静态产物，scp 到 Nginx 目录；路由用 hash 模式（免 Nginx history 回退配置，部署更简） |
| 环境 | `.env.production` 存 API base 路径（空串走同域反代） |

## 8. M1 交付范围与验收

| 范围 | 内容 |
|---|---|
| 交付页面 | 今日简报、候选池、个股详情、判断列表（只读）、系统中心（运行看板+用量+配置只读） |
| 占位空态 | 持仓、复盘中心入口显示「M2/M3 上线」 |
| 全局能力 | 登录、全局搜索、Layout、StatusBadge、ReportRenderer（含溯源）、手动单股分析、未分析标的空态（含淘汰原因展示） |
| 验收标准 | 晚间速览场景走通：打开首页 → 30 秒内完成四问 → 点进候选 → 展开因子明细 → 进入个股报告 → 折叠区展开 → 数字溯源弹层可查；全程无卡死、无报错、无需查看原始数据表。偶发查证场景走通：搜索任意股票 → 已分析直达详情 / 近期被淘汰可见原因 / 从未分析可一键发起手动分析 |

M2 补持仓模块，M3 实化判断验证与复盘中心。原则：**每个里程碑前端只加模块、不改已有页面结构**。
