## 4. 与设计文档的偏差（均已登记，按「更严/更可测」处理）

| # | 偏差 | 理由 | 登记位置 |
|---|---|---|---|
| D1 | 估值事实数值写成 `{value, unit}` 指标叶子，而非详案 5.4 示例的裸数字 | L3 的 `FactMetrics`/`FactsUsageValidator` 只认叶子；裸数字无法做「名+值+单位」三重比对 | SPEC ⑦ + 本文 |
| D2 | 估值事实新增 `window{start_trade_date,end_trade_date,sample_days}` | 详案 5.5 要求「窗口不足必须降级」，窗口边界必须是可引用事实 | SPEC ⑦ |
| D3 | 窗口起点用「自然年减法」而非「往前数 750 个交易日」 | 后者依赖交易日历，会把「日历未回填」变成单元失败；真实覆盖由 `sample_days` 记录 | SPEC ⑦ |
| D4 | 降级判断也需要 `report_id`：写一条 `status=DEGRADED`、`file_path=NULL` 的 `report` 占位行 | `judgment.report_id NOT NULL` 与「降级仅事实存档」冲撞；真实报告归档属 T18 | 《技术架构》§4.4 落地说明 + 本文 |
| D5 | `daily_basic` 新增非唯一索引 `idx_daily_basic_ts_code` | 唯一键 `(trade_date,ts_code)` 前缀支撑不了「按标的回查三年」，分页读数必须靠它 | `db/schema.sql` 注释 |
| D6 | `judgment.expire_at` 实体用 `String`（ISO 文本） | 该列是 T2 登记的 `DATE` 类型例外（附录 E6），避免新增 `LocalDate` 类型处理器 | `JudgmentEntity` javadoc |
| D7 | `method_version` 由调用方经 `MethodSnapshot` 传入 | 版本快照与启动期强校验属 T16；存档器不伪造版本来源 | `MethodSnapshot` javadoc |
| D8 | 单元 Spec 落 `docs/units/{unit_id}/SPEC.md` | 文档原文 `units/{unit_id}/SPEC.md`，但 `units/` 是 Java 包路径；`docs/units/` 一处承载 | 附录变更历史（2026-11-26） |
| D9 | `judgment.confidence` 保持三档枚举（不改 `DECIMAL`） | 详案 3.1/3.2 定义置信度为枚举；`VARCHAR(4)` 对单字中文足够 | 附录 P1-18 |
