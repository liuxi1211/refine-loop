## 七、数据库引擎迁移：MySQL → SQLite

> 迁移日期：2026-11-24。本节为迁移的完整记录；实施层偏差登记为 **D12**（§四），《架构》《任务计划》《README》已同步改写，历史实施计划（`.trae/documents/t2-t5-datacenter-plan.md`）只在文末追加附录、原文不改。

### 7.1 迁移动机

1. **单机个人系统**：不需要独立数据库服务进程与账号体系——免安装、免运维（无 3306 端口监听、无 mysqld、无 mysqldump 依赖）；
2. **单文件备份**：库文件即全部数据，复制或 `VACUUM INTO` 即可备份，恢复即替换文件；
3. **测试与生产同引擎**：原 `H2(MODE=MySQL)` 只能近似验证，schema 需做兼容变换（去 `STORED`、`IF()`→`CASE WHEN` 等）；迁移后单测直接在真实 SQLite 上执行，**验证即生产行为**；
4. **与项目规模匹配**：单机、盘后批处理 + 运维查询、单写者，SQLite（WAL）足够；SQL 集中在 MyBatis Mapper/Provider 层 + 注册表驱动（2026-11-24 ORM 化后），未来数据量/并发上来可回退 MySQL。

### 7.2 变更清单

| 层 | 变更前（MySQL 8 + H2 测试） | 变更后（SQLite 3） |
|---|---|---|
| 依赖 | `mysql-connector-j`（runtime）+ `h2`（test） | `org.xerial:sqlite-jdbc:3.50.3.0`（runtime）；移除 MySQL 驱动与 H2；MyBatis-Plus 已启用为 ORM 主框架（D13，原「T6+ 业务表 ORM 基座」表述作废） |
| schema | MySQL 方言：`AUTO_INCREMENT`、`ENGINE=InnoDB`、表/列 `COMMENT`、`JSON` 列、`ON UPDATE CURRENT_TIMESTAMP`、`UNIQUE KEY` | SQLite 方言（`db/schema.sql`，1329 行）：`INTEGER PRIMARY KEY AUTOINCREMENT`、全部 `CREATE TABLE IF NOT EXISTS` / `CREATE UNIQUE INDEX IF NOT EXISTS`、JSON 语义列改 TEXT、生成列 `CASE WHEN superseded = 0 THEN 1 ELSE NULL END STORED` + `uk_active` 唯一索引、时间戳默认 `datetime('now','localtime')`、无 `ON UPDATE`；**58 表 + 69 个索引（46 个唯一索引）**；原 COMMENT 保留为 `-- [原 MySQL 表注释]` 注释行 |
| 构建期 | schema 手工执行 | Maven resources 把仓库根 `db/schema.sql` 复制进 classpath（`target/classes/db/schema.sql`），运行期与单测共用同一份 DDL |
| 运行期初始化 | 手工建库 + 执行 schema | 新增 `config/SqliteSchemaInitializer`（`@PostConstruct`）：解析数据源 URL、创建库文件父目录 → 执行 schema（全部 `IF NOT EXISTS`，幂等，可反复启动）；非 SQLite URL 跳过；执行失败 fail-fast |
| 数据源 | `jdbc:mysql://...` + `DB_USER`/`DB_PASSWORD` | `jdbc:sqlite:./data/refine_loop.db?journal_mode=WAL&busy_timeout=5000&date_class=TEXT&foreign_keys=on&synchronous=NORMAL`；Hikari 连接池 8；生产默认 `/data/refine-loop/db/refine_loop.db`；**无 `DB_USER`/`DB_PASSWORD`** |
| SQL 方言 | `ON DUPLICATE KEY UPDATE` / `INSERT IGNORE` | `INSERT ... ON CONFLICT (键) DO UPDATE SET 列 = excluded.列`；表里只有键列时 `INSERT OR IGNORE`（注解 SQL / `TushareSqlProvider` 生成） |
| 并发写 | InnoDB 行锁，连接池并发写 | SQLite 单写者：`IngestTableWriter` 增加进程内 `ReentrantLock` 把落库串行化（HTTP 拉数并发不变），批量语句跑在 `MyBatisBatchExecutor` 的 BATCH 会话里，配合 WAL + `busy_timeout=5000` 避免 `SQLITE_BUSY` |
| 运维 API 元数据 | `information_schema`（表/列/近似行数 `TABLE_ROWS`） | 行数统计改精确 `COUNT(*)`（`rowCountApprox` 恒 `false`）；列元数据用 `PRAGMA table_info`；表清单来自 `sqlite_master`；查询经 `TushareTableMapper` / `QualityQueryMapper` / `OpsStatsMapper`（MyBatis） |
| 测试基座 | `H2 MODE=MySQL` 内存库 + schema 兼容变换 | `support/SchemaTestSupport`：在 `target/test-db/` 建随机名 SQLite 临时库、逐测试方法重建；`schema/SchemaH2Test` → `schema/SchemaSqliteTest`；`ApplicationStartupTest` 改为验证「首启自动建库 + 运维 API 立即可用」 |
| 文档 | MySQL/H2 表述 | 本报告第七节 + D12；`README.md`、`docs/技术架构与模块设计.md`（§0/§1/§2.1/§2.2/§3/§4.1/§5.2/§8/§10）、`docs/开发任务计划.md`（Phase A 说明、T2、T23）已改写；历史实施计划仅文末追加附录；`Tushare接口对接手册.md` 为接口契约层，无 MySQL 表述、无需改动 |

### 7.3 与 MySQL 的能力差异与取舍

| # | 能力差异 | 取舍 / 落地方式 |
|---|---|---|
| 1 | 无 `information_schema` | 表清单用 `sqlite_master`，列/索引元数据用 `PRAGMA table_info` / `index_list` / `index_info`；行数用精确 `COUNT(*)`（无近似值） |
| 2 | 无表/列 `COMMENT` | schema 内每张表保留 `-- [原 MySQL 表注释] <原注释>` 注释行；`SchemaSqliteTest` 解析 schema 文本断言注释存在 |
| 3 | 无 `ON UPDATE CURRENT_TIMESTAMP` | 更新时间列由应用显式写入（如 `sys_config.updated_at = excluded.updated_at`） |
| 4 | 单写者（同一时刻仅一个写事务） | WAL（1 写 + N 读）+ `busy_timeout=5000`；`IngestTableWriter` 进程内 `ReentrantLock` 把落库串行化，拉数并发不变；查询走读连接 |
| 5 | DECIMAL 精度不强制（类型亲和性存储） | 业务侧统一按 `BigDecimal` 处理与序列化，金额/比率计算不依赖数据库精度 |
| 6 | 行数统计无近似值 | 运维 API 全部精确 `COUNT(*)`（`rowCountApprox` 字段恒 `false`），对本项目规模（百万级行情表）足够 |
| 7 | 回退成本 | SQL 集中在 MyBatis Mapper/Provider + `TushareTableRegistry` 元数据驱动，方言点极少（建表/upsert/元数据查询）；若未来数据量/并发上来，替换回 MySQL 仅需改 schema、数据源配置与少数方言点 |

## 八、数据访问层 ORM 化改造（MyBatis-Plus 落地）

> 改造日期：2026-11-24（与数据库引擎迁移同日）。本节为 ORM 化的完整记录，实施层偏差登记为 **D13**（§四）；原 **D2 / D11 已被本次改造取代**。同步文档：《架构》§1（选型与依赖登记）/§3（包结构与数据访问层约定）/§4.1（数据接入）/§5.2（JSON 载荷）/§10（ADR-2 修订 + ADR-12 新增）；《任务计划》Phase A 说明与 T4；根 `README.md`；《契约》头部说明。

### 8.1 动机

1. **选型与实现不一致**：`pom.xml` 自 T2 起就登记了 `mybatis-plus-spring-boot3-starter 3.5.15`，但仅作为「后续 ORM 基座保留」，生产落库全走 `JdbcTemplate`——用户明确指出「数据库 ORM 不是 MyBatis 吗，怎么直接用 JdbcTemplate」，与《架构》§1 的 ORM 选型直接冲突；
2. **SQL 散落业务层**：JdbcTemplate 直连使 SQL 字符串分布在 10 个服务（写入器 / 作业 / 日志 / 配置 / 质量门 / 运维查询 / 启动初始化 / 限流计数），实体映射、参数绑定、类型转换各写一套，改一处口径要翻多处；
3. **SQLite 方言与类型口径需要收敛**：迁移 SQLite 后 `date_class=TEXT`，`LocalDateTime` 必须统一「文本时间戳」口径（否则 `created_at >= ?` 文本比较会错位），`ON CONFLICT` / `PRAGMA` 等 SQLite 方言点也需要集中到单一数据访问层。

### 8.2 分层方案

| 层 | 位置 | 职责与要点 |
|---|---|---|
| 业务表 ORM | `data/entity` + `data/mapper`（MyBatis-Plus `BaseMapper` / `LambdaQueryWrapper`） | `ingest_log` / `sys_config` / `rate_limit_counter` / `quality_check_log` 四张业务表；`sys_config` upsert 用注解 `ON CONFLICT (config_key) DO UPDATE`，`rate_limit_counter` 用 `ON CONFLICT ... DO UPDATE SET call_count = call_count + 1` 原子累加 |
| 41 张镜像表 | `data/provider/TushareSqlProvider` + `data/mapper/TushareTableMapper` | 保留「元数据驱动」：按「表名 + 列串 + 幂等键」生成 INSERT / `ON CONFLICT` / DELETE / COUNT / MAX / GROUP BY / 预览 / `PRAGMA table_info`；**不写 41 份 XML 或逐表 Mapper**（列集合由注册表 `fields` 决定，逐表 Mapper 必然漂移） |
| 固定业务/运维查询 | `TushareLookupMapper` / `QualityQueryMapper` / `OpsStatsMapper` | 交易日历（SSE/任意交易所）、在市股票清单、指数清单、L1 行业代码；质量门聚合（当日 daily 行数/在市总数/adj 行数/close≤0 行数/MAX 交易日/MAX 公告日/trade_cal is_open）；今日作业状态分布与限流调用合计 |
| 批量写 | `data/batch/MyBatisBatchExecutor` | `SqlSessionTemplate(ExecutorType.BATCH)` + `TransactionTemplate`；500 行/批 flush；`replaceAll` / `deleteAndInsertBlock` 用「同一 BATCH 会话 + 一个事务」保证先删后插原子 |
| DDL / 元数据 | `config/SqliteSchemaInitializer`（MyBatis `ScriptRunner`）/ `TushareTableMapper.tableInfo`（`PRAGMA table_info`） | 生产代码因此**零 `JdbcTemplate`** |
| 配置 | `config/MyBatisPlusConfig`（`@MapperScan("com.arthur.refineloop.data.mapper")`）+ `application.yml` 的 `mybatis-plus.*` | `map-underscore-to-camel-case: true`、`jdbc-type-for-null: NULL`（SQLite 必须）、`type-handlers-package`、`global-config.db-config`（`id-type: auto`、insert/update `not_null` 让 schema DEFAULT 生效）、`mapper-locations` 占位 |

**改动清单**：新增 `data/` 包 15 个文件（entity 4 / mapper 8 / provider 1 / batch 1 / handler 1）、`config/MyBatisPlusConfig`；`IngestLogService`、`SysConfigService`、`IngestTableWriter`、`IngestJobService`、`DataQualityGate`、`QualityCheckLogStore`、`TableOpsService`、`StatsService`、`SqliteSchemaInitializer`、`TushareConfig` 共 10 个服务改为 Mapper 构造注入；删除 `JdbcRateLimitCounterRecorder`，新增 `tushare/ratelimit/MybatisRateLimitCounterRecorder`；`support/SchemaTestSupport` 增加 `sqlSessionFactory` / `mapper` / `batchExecutor` 三个构造器，使单测与被测服务使用同一套 MyBatis 配置（Mapper 由测试侧传入，被测服务不再接收 `JdbcTemplate`）。

### 8.3 关键实现

| # | 主题 | 落地方式 |
|---|---|---|
| 1 | 实体与字段映射 | 实体用 `@TableName` + `@TableId(type = IdType.AUTO)`，字段与 `db/schema.sql` 一一对应；`map-underscore-to-camel-case` 负责列名转换；JSON 语义列（`quality_check_log.items`）仍用 String + 应用侧序列化（`QualityCheckLogStore` 用 Jackson），不建 JSON TypeHandler |
| 2 | 时间类型口径 | `SqliteLocalDateTimeTypeHandler`：`LocalDateTime` ↔ SQLite 文本时间戳（`setTimestamp` / `getTimestamp`），与 `date_class=TEXT`、`DEFAULT datetime('now','localtime')` 同口径；`DataAccessLayerTest` 断言库内 `typeof(...)='text'` 且写入/读出值完全一致 |
| 3 | 幂等 upsert / 原子累加 | 业务表用注解 `@Insert` 的 SQLite `ON CONFLICT (键) DO UPDATE SET 列 = excluded.列`（`sys_config`），计数用 `ON CONFLICT ... DO UPDATE SET call_count = call_count + 1` 保证并发下不丢计数；41 表 upsert 由 Provider 生成同样方言 |
| 4 | 动态 SQL 安全 | `TushareSqlProvider` 对表名/列名/排序方向做 `[A-Za-z_][A-Za-z0-9_]*` 正则白名单校验，值一律 `#{...}` 预编译绑定（NULL 显式 `jdbcType=NULL`），不做字符串拼接；调用方（`IngestTableWriter` / 运维服务）先按注册表校验一层，Provider 再兜底 |
| 5 | 批量与事务 | 批量写统一 `MyBatisBatchExecutor`（500 行/批，`flushStatements()`），保留手册 3.3「HTTP 不在事务内」纪律；**同一事务内不得混用不同 `ExecutorType` 的会话**（MyBatis-Spring 限制）——「先删后插」的删除与插入都在同一 BATCH Mapper 上执行、由同一个 `TransactionTemplate` 提交 |
| 6 | SQLite 单写者 | `IngestTableWriter` 进程内 `ReentrantLock` 串行化落库（HTTP 并发拉数不变），配合 `busy_timeout=5000` + WAL 避免 `SQLITE_BUSY`；运维行数统计走精确 `COUNT(*)`、列元数据走 `PRAGMA table_info`（均为 Mapper） |

### 8.4 验证

- **测试全绿**：`15 个测试类 / 111 个用例`（0 失败 / 0 错误 / 0 跳过），其中新增 `data/DataAccessLayerTest` 5 例：`LocalDateTime` 类型处理器写入/读出一致、`sys_config` `ON CONFLICT` upsert 同 key 只有一行且值更新、`rate_limit_counter` 按 api+分钟原子累加、`MyBatisBatchExecutor` 动态表 1200 行批量写入且重跑幂等、`quality_check_log` 实体写入 + `LambdaQueryWrapper` 查询（见 §3.1）；
- **真实启动与读写**：`ApplicationStartupTest`（3 例）验证首启自动建库建表后 41 表总览可用；`it/OpsApiIntegrationTest`（6 例）在真实 Spring 装配 + 真实 SQLite 上完成运维 API 读写、每日开关留痕、质量门 run+latest+history 落库——全部走 MyBatis 路径；
- **生产零 `JdbcTemplate`**：`src/main/java` 检索 `JdbcTemplate` 仅剩注释性说明（TushareConfig / SqliteSchemaInitializer / TushareSqlProvider / MyBatisBatchExecutor 的说明文字）；`JdbcTemplate` 引用仅存在于测试夹具/断言（`SchemaTestSupport` 建库造数、`DataAccessLayerTest` 等校验行数）；
- **同源配置**：`SchemaTestSupport.sqlSessionFactory/mapper/batchExecutor` 与被测服务共用同一套 MyBatis 配置（驼峰、`jdbcTypeForNull`、类型处理器、BATCH），避免「测试通过但生产映射不一致」。

### 8.5 遗留与取舍

1. **41 张镜像表仍是动态 Provider，不做逐表 Mapper**：列集合的唯事实源是 `TushareTableRegistry.fields`（由 `RegistrySchemaConsistencyTest` 逐列守护），逐表手写 Mapper/XML 会与注册表漂移，维护成本 > 类型化收益——这是原 D2 决策意图的延续，只是执行层由 `JdbcTemplate` 换成 MyBatis；
2. `mapper-locations: classpath*:/mapper/**/*.xml` 当前无 XML，仅作未来扩展占位（自定义 SQL 现为注解 + Provider）；
3. JSON 语义列仍为 String + 应用侧序列化（`quality_check_log.items`），未来业务表（`unit_fact` / `judgment`）可按需引入 MyBatis-Plus JSON TypeHandler + record 映射；
4. `spring-boot-starter-jdbc` 保留（数据源/事务管理器 + 测试夹具），但生产代码不再直接使用 `JdbcTemplate`；
5. 单写者锁为进程内实现，若未来多实例部署需升级为跨进程锁（见第五节第 7 项，属 M1 单服务器范围外）。
